## 1.1 Why classes exist

  

Before classes, you bundle related data in a dict and pass it around:

  

```python

account = {"owner": "Abhas", "balance": 0}

  

def deposit(acc, amount):

    acc["balance"] += amount

  

def withdraw(acc, amount):

    if amount > acc["balance"]:

        raise ValueError("Insufficient funds")

    acc["balance"] -= amount

  

deposit(account, 1000)

withdraw(account, 300)

print(account["balance"])  # 700

```

  

This works but has problems:

  

- Nothing stops `account["balnce"] = 999` (typo creates a new key silently).

- The functions and the data are not connected — anyone can mutate `balance` directly.

- There's no way to guarantee an account always starts in a valid state.

  

A **class** bundles data (**attributes**) and behavior (**methods**) into one unit, and

lets you control how that unit is created and mutated. An **object** (a.k.a. **instance**)

is one concrete thing built from that class.

  

```python

class Account:

    def __init__(self, owner, balance=0):

        self.owner = owner

        self.balance = balance

  

    def deposit(self, amount):

        self.balance += amount

  

    def withdraw(self, amount):

        if amount > self.balance:

            raise ValueError("Insufficient funds")

        self.balance -= amount

  
  

acc = Account("Abhas", 1000)

acc.withdraw(300)

print(acc.balance)  # 700

```

  

**Mental model:** a class is a blueprint; an instance is a house built from it. Each

house has its own values (its own `owner`, its own `balance`) but shares the same

floor plan (the methods).

## 1.2 `__init__`, `self`, and instances

  

```python

class Point:

    def __init__(self, x, y):   # the "initializer" / constructor

        self.x = x              # store x on THIS instance

        self.y = y

  

p = Point(3, 4)   # Python calls Point.__init__(p, 3, 4) for you

print(p.x, p.y)   # 3 4

```

  

**What `self` really is.** When you call `p.some_method(arg)`, Python rewrites it as

`Type.some_method(p, arg)`. The instance is passed as the first positional argument.

By convention that parameter is named `self`. It's not a keyword — you *could* name it

`this` — but never do; every Python reader expects `self`.

  

```python

class Demo:

    def show(self):

        print(self)

  

d = Demo()

d.show()          # <__main__.Demo object at 0x...>

Demo.show(d)      # identical call, written explicitly

```

  

`__init__` is **not** a constructor in the C++/Java sense. The object is already

created by the time `__init__` runs (the real constructor is `__new__`, covered later).

`__init__`'s job is to *initialize* an already-existing blank instance.

## 1.3 Instance attributes vs class attributes

  

An **instance attribute** lives on one object. A **class attribute** lives on the class

and is shared by all instances.

  

```python

class Dog:

    species = "Canis familiaris"   # class attribute — shared

  

    def __init__(self, name):

        self.name = name           # instance attribute — per-object

  

a = Dog("Rex")

b = Dog("Fido")

print(a.species, b.species)   # Canis familiaris Canis familiaris (same object)

print(a.name, b.name)         # Rex Fido

```

  

**Attribute lookup order:** when you read `a.species`, Python checks the *instance*

first, then the *class*, then base classes. When you *write* `a.species = "x"`, it

always creates an **instance** attribute that shadows the class one:

  

```python

a.species = "Wolf"

print(a.species)   # Wolf   (instance attr shadows class attr)

print(b.species)   # Canis familiaris   (unaffected)

print(Dog.species) # Canis familiaris   (class attr untouched)

```

  

### The classic mutable-class-attribute trap

  

```python

class Portfolio:

    holdings = []            # ⚠️ shared list across ALL instances

  

    def add(self, ticker):

        self.holdings.append(ticker)

  

p1 = Portfolio()

p2 = Portfolio()

p1.add("INFY")

print(p2.holdings)   # ['INFY']  😱  p2 sees p1's data

```

  

Because `holdings` is a single shared list, both instances mutate the same object.

Fix: create the mutable state per-instance in `__init__`.

  

```python

class Portfolio:

    def __init__(self):

        self.holdings = []   # ✅ each instance gets its own list

  

    def add(self, ticker):

        self.holdings.append(ticker)

```

  

**Rule of thumb:** class attributes are fine for constants and defaults; never use a

mutable object (list/dict/set) as a class attribute unless you *want* it shared.

  

### Exercise 1.3

  

Create a `Counter` class where each instance counts its own increments, but the class

also tracks how many `Counter` objects have ever been created (across all instances).

```python

class Counter:

    total_created = 0          # class attribute: shared tally

  

    def __init__(self):

        self.count = 0         # instance attribute: per-object

        Counter.total_created += 1   # increment the CLASS attribute explicitly

  

    def increment(self):

        self.count += 1

  

c1 = Counter(); c1.increment(); c1.increment()

c2 = Counter(); c2.increment()

print(c1.count, c2.count)          # 2 1

print(Counter.total_created)       # 2

```

  

Note we write `Counter.total_created += 1`, not `self.total_created += 1`. The latter

would read the class value but *write* a new instance attribute, breaking the tally.

## 1.4 Three kinds of methods

  

```python

class Temperature:

    scale = "Celsius"

  

    def __init__(self, degrees):

        self.degrees = degrees

  

    # 1. INSTANCE method — receives the instance as `self`

    def to_fahrenheit(self):

        return self.degrees * 9 / 5 + 32

  

    # 2. CLASS method — receives the class as `cls`; great for alternate constructors

    @classmethod

    def from_fahrenheit(cls, f):

        return cls((f - 32) * 5 / 9)

  

    # 3. STATIC method — receives nothing special; just namespaced under the class

    @staticmethod

    def is_freezing(celsius):

        return celsius <= 0

  
  

t = Temperature(25)

print(t.to_fahrenheit())              # 77.0

t2 = Temperature.from_fahrenheit(212) # alternate constructor -> Temperature(100.0)

print(t2.degrees)                     # 100.0

print(Temperature.is_freezing(-4))    # True

```

  

- **Instance method** — needs a specific object. The default.

- **`@classmethod`** — receives the class (`cls`). The killer use case is **alternate

  constructors** (`from_fahrenheit`, `from_json`, `from_csv_row`, …). Using `cls(...)`

  instead of `Temperature(...)` means subclasses get the right type back automatically.

- **`@staticmethod`** — a plain function that logically belongs to the class but needs

  neither the instance nor the class. Use it for helpers.

  

> `@classmethod` and `@staticmethod` are your first real decorators — you're already

> using decorators before Part 2. We'll demystify exactly how they work later.

## 1.5 Encapsulation: public, "protected", "private"

  

Python has **no real access control**. Instead it uses naming conventions plus one

lightweight enforcement mechanism.

  

```python

class BankAccount:

    def __init__(self, balance):

        self.balance = balance      # public: use freely

        self._pin = "0000"          # _single: "internal, don't touch" (convention only)

        self.__ledger = []          # __double: name-mangled (weakly private)

```

  

- `name` — public API.

- `_name` — a hint: "internal, may change, use at your own risk." Nothing enforces it.

- `__name` — **name mangling**: Python renames `__ledger` to `_BankAccount__ledger`.

  This isn't security; it's to avoid *accidental* clashes in subclasses.

  

```python

acc = BankAccount(100)

print(acc.balance)            # 100  (public)

print(acc._pin)               # 0000 (works, but you were warned)

# print(acc.__ledger)         # AttributeError!

print(acc._BankAccount__ledger)  # []  (mangled name — it's still reachable)

```

  

**Takeaway:** encapsulation in Python is a social contract, not a lock. The tool that

lets you *guard* attribute access properly is the **property** — next.

## 1.6 Properties — computed & guarded attributes

  

A **property** lets a method masquerade as an attribute. This is huge: you can start

with a plain attribute and later add validation *without changing any calling code*.

  

```python

class Circle:

    def __init__(self, radius):

        self.radius = radius        # goes through the setter below (validates)

  

    @property

    def radius(self):               # getter

        return self._radius

  

    @radius.setter

    def radius(self, value):        # setter — runs on every assignment

        if value <= 0:

            raise ValueError("radius must be positive")

        self._radius = value

  

    @property

    def area(self):                 # read-only computed attribute

        return 3.141592653589793 * self._radius ** 2

  
  

c = Circle(5)

print(c.radius)   # 5      (calls the getter)

print(c.area)     # 78.53… (computed on access; no parentheses!)

c.radius = 10     # calls the setter -> validates -> stores

# c.radius = -1   # ValueError: radius must be positive

# c.area = 50     # AttributeError: can't set attribute (no setter defined)

```

  

Key points:

  

- `@property` turns `radius()` into something you access as `c.radius` (no parens).

- `@radius.setter` defines what happens on `c.radius = value`.

- Omit the setter → the property is **read-only** (like `area`).

- The real data lives in a differently-named attribute (`_radius`) to avoid infinite

  recursion (if the getter returned `self.radius`, it would call itself forever).

  

There's also `@radius.deleter` for `del c.radius`, used far less often.

  

**When to use a property vs a plain attribute:** start with a plain attribute. Promote

it to a property the moment you need validation, a computed value, logging, or

lazy-loading. Because the syntax is identical, callers never notice.

## 1.7 Inheritance and `super()`

  

Inheritance lets a class reuse and extend another. The child is a **subclass**; the

parent is a **base/super class**.

  

```python

class Animal:

    def __init__(self, name):

        self.name = name

  

    def speak(self):

        return "..."

  

    def describe(self):

        return f"{self.name} says {self.speak()}"

  
  

class Dog(Animal):                 # Dog inherits from Animal

    def speak(self):               # override

        return "Woof"

  
  

class Cat(Animal):

    def __init__(self, name, indoor):

        super().__init__(name)     # call Animal.__init__ to set self.name

        self.indoor = indoor       # then add our own

  

    def speak(self):

        return "Meow"

  
  

print(Dog("Rex").describe())   # Rex says Woof

print(Cat("Milo", True).speak())  # Meow

```

  

- `class Dog(Animal)` — Dog **is-an** Animal.

- Overriding = defining a method with the same name; the child's wins.

- `super().__init__(name)` — call the parent's version. Always use `super()` rather

  than `Animal.__init__(self, name)`; it's what makes multiple inheritance work.

- **Polymorphism**: `describe()` (defined once in `Animal`) calls `self.speak()`, which

  resolves to whichever subclass's version — the parent code drives child behavior.

  

### `isinstance` and `issubclass`

  

```python

d = Dog("Rex")

print(isinstance(d, Dog))      # True

print(isinstance(d, Animal))   # True  (Dog IS-A Animal)

print(issubclass(Dog, Animal)) # True

```

  

### Multiple inheritance and the MRO

  

A class can inherit from several bases. Python resolves which method to use via the

**Method Resolution Order (MRO)**, computed by the C3 linearization algorithm.

  

```python

class A:

    def greet(self): return "A"

  

class B(A):

    def greet(self): return "B -> " + super().greet()

  

class C(A):

    def greet(self): return "C -> " + super().greet()

  

class D(B, C):

    def greet(self): return "D -> " + super().greet()

  

print(D().greet())        # D -> B -> C -> A

print([cls.__name__ for cls in D.__mro__])   # ['D', 'B', 'C', 'A', 'object']

```

  

Read that carefully: even though `B`'s `super()` textually refers to `A`, in the

context of a `D` instance, `super()` inside `B` actually calls `C` — because the MRO

for `D` is `D → B → C → A`. This is the famous **diamond problem**, and Python's MRO

solves it so each class runs exactly once. This is *why* you use `super()` and not

hard-coded parent names.

  

> **Design note:** deep or wide inheritance trees are a common source of bugs. Prefer

> shallow hierarchies, and favor **composition** (Section 1.13) when "is-a" doesn't

> truly hold.

## 1.8 Dunder (magic) methods — make objects behave like built-ins

  

"Dunder" = **d**ouble **under**score. These special methods let your objects integrate

with Python's syntax: printing, comparison, arithmetic, indexing, iteration, and more.

  

### `__repr__` vs `__str__`

  

```python

class Money:

    def __init__(self, rupees):

        self.rupees = rupees

  

    def __repr__(self):

        # unambiguous, for developers/debugging; ideally valid Python

        return f"Money({self.rupees!r})"

  

    def __str__(self):

        # readable, for end users

        return f"₹{self.rupees:,.2f}"

  

m = Money(1234.5)

print(m)          # ₹1,234.50      (uses __str__)

print(repr(m))    # Money(1234.5)  (uses __repr__)

m                 # in a REPL, shows Money(1234.5) via __repr__

[m]               # containers use __repr__ of elements: [Money(1234.5)]

```

  

**Rule:** always define `__repr__`. Define `__str__` only if users need a prettier form.

If only `__repr__` exists, `str()` falls back to it.

  

### Equality and ordering

  

```python

from functools import total_ordering

  

@total_ordering                    # fills in <=, >, >= from __eq__ and __lt__

class Version:

    def __init__(self, major, minor):

        self.major, self.minor = major, minor

  

    def __eq__(self, other):

        if not isinstance(other, Version):

            return NotImplemented

        return (self.major, self.minor) == (other.major, other.minor)

  

    def __lt__(self, other):

        if not isinstance(other, Version):

            return NotImplemented

        return (self.major, self.minor) < (other.major, other.minor)

  

    def __hash__(self):            # define if you want to use it in sets/dict keys

        return hash((self.major, self.minor))

  

    def __repr__(self):

        return f"Version({self.major}, {self.minor})"

  

print(Version(1, 2) == Version(1, 2))   # True

print(Version(1, 2) < Version(1, 10))   # True

print(sorted([Version(2, 0), Version(1, 5)]))  # [Version(1, 5), Version(2, 0)]

```

  

Notes:

  

- Returning `NotImplemented` (not raising) lets Python try the other operand's method.

- If you define `__eq__`, Python sets `__hash__` to `None` (your object becomes

  unhashable) unless you also define `__hash__`. Objects used as set members or dict

  keys must be hashable — and equal objects must have equal hashes.

- `@total_ordering` saves you writing all six comparison methods.

  

### Making objects callable, indexable, iterable, and length-aware

  

```python

class Playlist:

    def __init__(self, songs):

        self._songs = list(songs)

  

    def __len__(self):                 # len(playlist)

        return len(self._songs)

  

    def __getitem__(self, index):      # playlist[0], and enables iteration + slicing

        return self._songs[index]

  

    def __setitem__(self, index, value):   # playlist[0] = "..."

        self._songs[index] = value

  

    def __contains__(self, song):      # "x" in playlist

        return song in self._songs

  

    def __iter__(self):                # explicit iteration (optional if __getitem__ exists)

        return iter(self._songs)

  

pl = Playlist(["a", "b", "c"])

print(len(pl))          # 3

print(pl[1])            # b

print("a" in pl)        # True

for s in pl: print(s)   # a b c

```

  

```python

class Adder:

    def __init__(self, n):

        self.n = n

  

    def __call__(self, x):    # makes the INSTANCE callable like a function

        return x + self.n

  

add5 = Adder(5)

print(add5(10))    # 15    -> Adder.__call__(add5, 10)

print(callable(add5))  # True

```

  

`__call__` is the bridge to Part 2: a **class-based decorator** is just a callable

object. Keep it in mind.

  

### Operator overloading

  

```python

class Vector:

    def __init__(self, x, y):

        self.x, self.y = x, y

  

    def __add__(self, other):          # self + other

        return Vector(self.x + other.x, self.y + other.y)

  

    def __mul__(self, scalar):         # self * scalar

        return Vector(self.x * scalar, self.y * scalar)

  

    def __rmul__(self, scalar):        # scalar * self  (reflected)

        return self * scalar

  

    def __eq__(self, other):

        return (self.x, self.y) == (other.x, other.y)

  

    def __repr__(self):

        return f"Vector({self.x}, {self.y})"

  

v = Vector(1, 2) + Vector(3, 4)

print(v)          # Vector(4, 6)

print(3 * Vector(1, 1))   # Vector(3, 3)  (uses __rmul__)

```

  

Common dunders worth knowing: `__add__ __sub__ __mul__ __truediv__ __floordiv__

__mod__ __pow__` (and their `__r*__` reflected and `__i*__` in-place variants),

`__neg__ __abs__ __round__`, `__bool__` (truthiness), `__format__` (f-string formatting).

  

### Context managers: `__enter__` / `__exit__`

  

```python

class Timer:

    def __enter__(self):

        import time

        self._start = time.perf_counter()

        return self                      # value bound to `as`

  

    def __exit__(self, exc_type, exc_val, exc_tb):

        import time

        self.elapsed = time.perf_counter() - self._start

        # return False (or None) -> propagate any exception; True -> suppress it

        return False

  

with Timer() as t:

    sum(range(1_000_000))

print(f"{t.elapsed:.4f}s")

```

  

`with` guarantees `__exit__` runs even if the block raises — perfect for files, locks,

DB connections. (There's an easier decorator-based way to write these, coming in 2.11.)

  

### Exercise 1.8

  

Create a `Fraction` class supporting `+` and `==`, with a clean `__repr__` like

`Fraction(1, 2)` and a `__str__` like `1/2`. (Don't worry about reducing to lowest

terms unless you want a bonus.)

  

<details><summary>Solution</summary>

  

```python

from math import gcd

  

class Fraction:

    def __init__(self, num, den):

        if den == 0:

            raise ZeroDivisionError("denominator cannot be 0")

        g = gcd(num, den)               # bonus: auto-reduce

        self.num, self.den = num // g, den // g

  

    def __add__(self, other):

        return Fraction(self.num * other.den + other.num * self.den,

                        self.den * other.den)

  

    def __eq__(self, other):

        return self.num * other.den == other.num * self.den

  

    def __repr__(self):

        return f"Fraction({self.num}, {self.den})"

  

    def __str__(self):

        return f"{self.num}/{self.den}"

  

print(Fraction(1, 2) + Fraction(1, 3))   # Fraction(5, 6)

print(str(Fraction(2, 4)))               # 1/2

print(Fraction(1, 2) == Fraction(2, 4))  # True

```

</details>

## 1.9 Abstract Base Classes (ABCs)

  

An ABC defines an interface that subclasses **must** implement. You can't instantiate an

ABC directly, and forgetting a required method fails loudly at construction time.

  

```python

from abc import ABC, abstractmethod

  

class Shape(ABC):

    @abstractmethod

    def area(self):

        ...

  

    @abstractmethod

    def perimeter(self):

        ...

  

    def describe(self):                  # concrete method shared by all shapes

        return f"area={self.area():.2f}, perimeter={self.perimeter():.2f}"

  
  

class Square(Shape):

    def __init__(self, side):

        self.side = side

  

    def area(self):

        return self.side ** 2

  

    def perimeter(self):

        return 4 * self.side

  
  

# s = Shape()     # TypeError: Can't instantiate abstract class Shape

print(Square(3).describe())   # area=9.00, perimeter=12.00

  

class Broken(Shape):

    def area(self): return 0

    # forgot perimeter()

  

# Broken()   # TypeError: Can't instantiate abstract class Broken with abstract method perimeter

```

  

Use ABCs when you're designing a **framework** where plugins/strategies must conform to

a contract. They turn "you forgot a method" from a runtime surprise into an immediate,

clear error.

## 1.10 Dataclasses — kill the boilerplate

  

Writing `__init__`, `__repr__`, and `__eq__` by hand for every data-holding class is

tedious. `@dataclass` generates them from type-annotated fields.

  

```python

from dataclasses import dataclass, field

  

@dataclass

class Trade:

    symbol: str

    qty: int

    price: float

    tags: list = field(default_factory=list)   # mutable default done right

  

    @property

    def value(self):

        return self.qty * self.price

  

t = Trade("INFY", 10, 1500.0)

print(t)              # Trade(symbol='INFY', qty=10, price=1500.0, tags=[])

print(t.value)       # 15000.0

print(t == Trade("INFY", 10, 1500.0))   # True  (auto __eq__)

```

  

Why `field(default_factory=list)` instead of `tags: list = []`? Same mutable-default

trap as functions — a bare `[]` would be shared across all instances. `default_factory`

runs the callable fresh for each instance.

  

Useful options:

  

```python

@dataclass(frozen=True)     # immutable: assignment after creation raises; makes it hashable

class Point:

    x: int

    y: int

  

@dataclass(order=True)      # generates <, <=, >, >= comparing fields as a tuple

class Score:

    points: int

    name: str

```

  

Reach for a dataclass whenever a class is mostly a **bundle of fields**. Reach for a

regular class when behavior dominates.

## 1.11 `__slots__` — memory & attribute discipline

  

By default each instance stores attributes in a per-instance `__dict__`, which is

flexible but memory-hungry and typo-prone. `__slots__` fixes the attribute set:

  

```python

class PointSlots:

    __slots__ = ("x", "y")     # only these attributes allowed; no __dict__

  

    def __init__(self, x, y):

        self.x, self.y = x, y

  

p = PointSlots(1, 2)

# p.z = 3    # AttributeError: 'PointSlots' object has no attribute 'z'

```

  

Benefits: substantially less memory per instance (matters when you create millions of

them — e.g., tick/bar objects), and you catch attribute typos immediately. Costs: you

lose dynamic attribute assignment and need care with inheritance and some libraries.

Use it for small, numerous, fixed-shape objects; skip it otherwise.

## 1.12 `__new__` vs `__init__` (advanced, optional)

  

`__new__` actually **creates and returns** the instance; `__init__` then initializes it.

You rarely override `__new__`, but it's needed for things like immutable subclasses or a

singleton:

  

```python

class Singleton:

    _instance = None

  

    def __new__(cls, *args, **kwargs):

        if cls._instance is None:

            cls._instance = super().__new__(cls)

        return cls._instance

  

a = Singleton()

b = Singleton()

print(a is b)   # True — same object every time

```

  

For 99% of classes, ignore `__new__` and just use `__init__`.

## 1.13 Composition over inheritance

  

Inheritance models **is-a** ("a Dog is an Animal"). Composition models **has-a**

("a Car has an Engine"). Overusing inheritance produces rigid, tangled hierarchies.

When the relationship isn't a genuine "is-a", compose:

  

```python

class Engine:

    def start(self):

        return "Engine started"

  

class GPS:

    def locate(self):

        return "12.97°N, 77.59°E"

  

class Car:

    def __init__(self):

        self.engine = Engine()     # HAS-A engine

        self.gps = GPS()           # HAS-A GPS

  

    def start(self):

        return self.engine.start()

  

    def where(self):

        return self.gps.locate()

  

c = Car()

print(c.start())   # Engine started

print(c.where())   # 12.97°N, 77.59°E

```

  

Swapping an `Engine` for an `ElectricMotor` is trivial with composition; with

inheritance you'd be refactoring a class tree. **Default to composition; use inheritance

only for true subtyping.**

## PART 1 MINI-PROJECT — a tiny order book

  

Build these classes:

  

1. `Order` (dataclass): `side` (`"BUY"`/`"SELL"`), `symbol`, `qty`, `price`. Add a

   `notional` property (`qty * price`).

2. `Portfolio`: holds a dict of `symbol -> net_qty`. Method `apply(order)` adjusts the

   position (BUY adds, SELL subtracts). Method `position(symbol)` returns net qty (0 if

   absent). Support `len(portfolio)` (number of symbols held) and `in` (symbol present).

3. A property `is_flat` that's `True` when every position is 0.

  

<details><summary>Solution</summary>

  

```python

from dataclasses import dataclass

  

@dataclass

class Order:

    side: str

    symbol: str

    qty: int

    price: float

  

    @property

    def notional(self):

        return self.qty * self.price

  
  

class Portfolio:

    def __init__(self):

        self._positions = {}

  

    def apply(self, order):

        delta = order.qty if order.side == "BUY" else -order.qty

        self._positions[order.symbol] = self._positions.get(order.symbol, 0) + delta

  

    def position(self, symbol):

        return self._positions.get(symbol, 0)

    def is_flat(self):

        return all(q == 0 for q in self._positions.values())

  

    def __len__(self):

        return sum(1 for q in self._positions.values() if q != 0)

  

    def __contains__(self, symbol):

        return self._positions.get(symbol, 0) != 0

  

    def __repr__(self):

        held = {s: q for s, q in self._positions.items() if q != 0}

        return f"Portfolio({held})"

  
  

p = Portfolio()

p.apply(Order("BUY", "INFY", 10, 1500))

p.apply(Order("BUY", "INFY", 5, 1510))

p.apply(Order("SELL", "INFY", 15, 1520))

print(len(p))               # 0

```

# PART 2 — DECORATORS

  

## 2.1 The prerequisites (nail these or decorators feel like magic)

  

### Functions are first-class objects

  

Functions can be assigned to variables, passed as arguments, returned from other

functions, and stored in data structures — exactly like ints or strings.

  

```python

def shout(text):

    return text.upper()

  

yell = shout               # assign the function object (no parens!)

print(yell("hi"))          # HI

  

def apply(func, value):    # pass a function as an argument

    return func(value)

  

print(apply(shout, "hello"))   # HELLO

```

  

### Closures — inner functions remember their enclosing scope

  

```python

def make_multiplier(factor):

    def multiply(x):           # inner function

        return x * factor      # 'factor' is captured from the enclosing scope

    return multiply            # return the inner function (a closure)

  

triple = make_multiplier(3)

print(triple(10))    # 30 — 'triple' remembers factor == 3

print(triple.__closure__[0].cell_contents)   # 3  (the captured value)

```

  

The returned `multiply` "closes over" `factor` — it keeps a reference even after

`make_multiplier` has returned. **This is the entire mechanism behind decorators.**

  

### `*args` and `**kwargs` — accept any arguments

  

```python

def anything(*args, **kwargs):

    print("positional:", args)     # a tuple

    print("keyword:", kwargs)      # a dict

  

anything(1, 2, x=3, y=4)

# positional: (1, 2)

# keyword: {'x': 3, 'y': 4}

```

  

A wrapper that must forward *any* call signature uses `(*args, **kwargs)` to receive and

`func(*args, **kwargs)` to forward. Memorize this pattern.

## 2.2 Your first decorator, built by hand

  

A **decorator** is just a function that takes a function and returns a (usually enhanced)

function. Let's build one that prints before and after a call.

  

```python

def logged(func):                       # 1. takes a function

    def wrapper(*args, **kwargs):       # 2. defines a replacement

        print(f"Calling {func.__name__}")

        result = func(*args, **kwargs)  # 3. call the original

        print(f"{func.__name__} returned {result!r}")

        return result                   # 4. don't forget to return!

    return wrapper                      # 5. return the replacement

  
  

def add(a, b):

    return a + b

  

add = logged(add)      # manually decorate: rebind 'add' to the wrapper

print(add(2, 3))

# Calling add

# add returned 5

# 5

```

  

The line `add = logged(add)` is the whole idea. The `@` syntax is pure sugar for it:

  

```python

@logged            # exactly equivalent to:  greet = logged(greet)

def greet(name):

    return f"Hi {name}"

  

greet("Abhas")

# Calling greet

# greet returned 'Hi Abhas'

```

  

So `@decorator` above a `def` means: define the function, then immediately pass it

through `decorator` and rebind the name to the result. Nothing more.

## 2.3 `functools.wraps` — don't lose your function's identity

  

The naive wrapper has a subtle bug: the decorated function's metadata (name, docstring)

gets replaced by the wrapper's.

  

```python

import functools

  

def logged_bad(func):

    def wrapper(*args, **kwargs):

        return func(*args, **kwargs)

    return wrapper

  

@logged_bad

def compute(x):

    "Compute something important."

    return x

  

print(compute.__name__)   # wrapper   😱  (should be 'compute')

print(compute.__doc__)    # None      😱  (lost the docstring)

```

  

`functools.wraps` copies the original's identity onto the wrapper:

  

```python

def logged(func):

    @functools.wraps(func)          # ← copies __name__, __doc__, __wrapped__, etc.

    def wrapper(*args, **kwargs):

        return func(*args, **kwargs)

    return wrapper

  

@logged

def compute(x):

    "Compute something important."

    return x

  

print(compute.__name__)   # compute

print(compute.__doc__)    # Compute something important.

print(compute.__wrapped__)  # <function compute ...>  (access the original)

```

  

**Always use `@functools.wraps(func)` on your wrapper.** It keeps debugging,

introspection, and documentation tools working. Every real-world decorator uses it.

## 2.4 A practical timing decorator

  

```python

import functools, time

  

def timed(func):

    @functools.wraps(func)

    def wrapper(*args, **kwargs):

        start = time.perf_counter()

        try:

            return func(*args, **kwargs)

        finally:                              # runs even if func raises

            elapsed = time.perf_counter() - start

            print(f"{func.__name__} took {elapsed*1000:.2f} ms")

    return wrapper

  

@timed

def slow_square(n):

    time.sleep(0.05)

    return n * n

  

slow_square(9)   # slow_square took ~50.xx ms

```

  

The `try/finally` ensures timing is reported even when the wrapped function throws — a

good habit for any decorator that must run cleanup.

## 2.5 Decorators that take arguments (the three-layer pattern)

  

To pass configuration to a decorator (e.g. `@repeat(3)`), you need **one more layer**:

a function that takes the arguments and *returns a decorator*.

  

```python

import functools

  

def repeat(times):                          # 1. decorator FACTORY (takes args)

    def decorator(func):                    # 2. the actual decorator (takes func)

        @functools.wraps(func)

        def wrapper(*args, **kwargs):       # 3. the wrapper (takes call args)

            result = None

            for _ in range(times):

                result = func(*args, **kwargs)

            return result

        return wrapper

    return decorator

  

@repeat(3)

def ping():

    print("ping")

  

ping()

# ping

# ping

# ping

```

  

Read the layers:

  

- `repeat(3)` runs first and returns `decorator` (with `times=3` captured in a closure).

- `@decorator` then wraps `ping` as usual.

- So `@repeat(3)` desugars to `ping = repeat(3)(ping)`.

  

Count the layers: **decorator with no args = 2 functions; decorator with args = 3.**

That extra layer trips up everyone at first; once you see it as "factory → decorator →

wrapper" it clicks.

  

### Optional-argument decorators (works with or without parentheses)

  

Making a decorator usable as both `@track` and `@track(label="x")` requires a small

trick:

  

```python

import functools

  

def track(func=None, *, label=""):

    if func is None:                        # called as @track(label=...)

        return functools.partial(track, label=label)

    @functools.wraps(func)                   # called as @track

    def wrapper(*args, **kwargs):

        print(f"[{label or func.__name__}] running")

        return func(*args, **kwargs)

    return wrapper

  

@track

def a(): pass

  

@track(label="important")

def b(): pass

  

a()   # [a] running

b()   # [important] running

```

```python
    return decorator

# attempt 1 failed: network down

# attempt 2 failed: network down

# success

```

</details>

## 2.6 Stacking (composing) decorators

  

You can apply several decorators to one function. They apply **bottom-up** (nearest the

`def` first), like nested function calls.

  

```python

import functools

  

def bold(func):

    @functools.wraps(func)

    def wrapper(*a, **k):

        return "<b>" + func(*a, **k) + "</b>"

    return wrapper

  

def italic(func):

    @functools.wraps(func)

    def wrapper(*a, **k):

        return "<i>" + func(*a, **k) + "</i>"

    return wrapper

  

@bold

@italic

def hello():

    return "hi"

  

print(hello())   # <b><i>hi</i></b>

```

  

`@bold @italic def hello` means `hello = bold(italic(hello))`. `italic` wraps first

(inner), then `bold` wraps that (outer). Order matters: swap them and you get

`<i><b>hi</b></i>`.

## 2.7 Class-based decorators

  

Recall `__call__` from 1.8: any object whose class defines `__call__` is callable. So a

**class instance can act as a decorator**. This is handy when the decorator needs to hold

state.

  

```python

import functools

  

class CountCalls:

    def __init__(self, func):

        functools.update_wrapper(self, func)   # like @wraps but for the instance

        self.func = func

        self.count = 0

  

    def __call__(self, *args, **kwargs):

        self.count += 1

        print(f"Call #{self.count} of {self.func.__name__}")

        return self.func(*args, **kwargs)

  

@CountCalls                      # say_hi = CountCalls(say_hi)

def say_hi():

    return "hi"

  

say_hi()   # Call #1 of say_hi

say_hi()   # Call #2 of say_hi

print(say_hi.count)   # 2   (state lives on the instance)

```

  

- `@CountCalls` over `say_hi` runs `say_hi = CountCalls(say_hi)`.

- Each call goes through `__call__`.

- The `count` state persists on the instance — cleaner than a closure with `nonlocal`

  for anything stateful.

  

For a **class-based decorator that takes arguments**, put the args in `__init__` and the

function in `__call__` (which then returns the wrapper):

  

```python

import functools

  

class RateLimited:

    def __init__(self, max_per_run):        # decorator arguments

        self.max_per_run = max_per_run

  

    def __call__(self, func):               # receives the function

        calls = 0

        @functools.wraps(func)

        def wrapper(*args, **kwargs):

            nonlocal calls

            if calls >= self.max_per_run:

                raise RuntimeError("rate limit exceeded")

            calls += 1

            return func(*args, **kwargs)

        return wrapper

  

@RateLimited(2)

def submit():

    return "ok"

  

print(submit()); print(submit())   # ok  ok

# submit()                          # RuntimeError: rate limit exceeded

```

## 2.8 Decorating methods

  

Decorators work on methods too — but remember the wrapper receives `self` as its first

positional argument (it's just part of `*args`).

  

```python

import functools

  

def log_method(func):

    @functools.wraps(func)

    def wrapper(self, *args, **kwargs):     # 'self' is explicit here for clarity

        print(f"{type(self).__name__}.{func.__name__} called")

        return func(self, *args, **kwargs)

    return wrapper

  

class Service:

    @log_method

    def fetch(self, url):

        return f"data from {url}"

  

Service().fetch("/api")

# Service.fetch called

```

  

If you'd written `wrapper(*args, **kwargs)` it would still work — `self` just rides

along inside `args`. Writing `self` explicitly is only for readability.

  

> **Gotcha:** a stateful function-based decorator (like a closure counter) applied to a

> method shares its state across *all instances*, because the wrapper is created once at

> class-definition time. If you need per-instance state, store it on `self` inside the

> wrapper, or use a descriptor.

## 2.9 Decorating a whole class

  

A class decorator receives the class object and returns a (usually modified) class.

  

```python

def add_repr(cls):

    def __repr__(self):

        fields = ", ".join(f"{k}={v!r}" for k, v in self.__dict__.items())

        return f"{cls.__name__}({fields})"

    cls.__repr__ = __repr__     # inject a method

    return cls

  

@add_repr

class Point:

    def __init__(self, x, y):

        self.x, self.y = x, y

  

print(Point(1, 2))   # Point(x=1, y=2)

```

  

`@dataclass` itself is exactly this kind of thing — a class decorator that inspects your

annotations and injects `__init__`, `__repr__`, `__eq__`, etc.

## 2.10 The built-in decorators you already rely on

  

Now that the mechanism is clear, revisit the ones you met in Part 1 plus the essential

standard-library ones.

  

### `@property`, `@staticmethod`, `@classmethod`

  

These are built-in decorators. Each returns a special **descriptor** object (see 2.12)

that changes how attribute access works. You now understand `@property` isn't magic —

it's a decorator returning a descriptor whose `__get__`/`__set__` route to your

getter/setter.

  

### `@functools.lru_cache` / `@functools.cache` — memoization for free

  

```python

import functools

  

@functools.lru_cache(maxsize=None)     # or just @functools.cache in 3.9+

def fib(n):

    return n if n < 2 else fib(n - 1) + fib(n - 2)

  

print(fib(100))            # instant, despite naive recursion

print(fib.cache_info())    # CacheInfo(hits=..., misses=..., ...)

fib.cache_clear()          # reset the cache

```

  

Caches results keyed by arguments (which must be hashable). Turns exponential recursion

into linear. `@cache` is `lru_cache(maxsize=None)`. Don't cache functions with side

effects or non-hashable args.

  

### `@functools.singledispatch` — function overloading by type

  

```python

from functools import singledispatch

  

@singledispatch

def describe(x):

    return f"unknown: {x!r}"

  

@describe.register

def _(x: int):

    return f"integer {x}"

  

@describe.register

def _(x: list):

    return f"list of {len(x)} items"

  

print(describe(5))         # integer 5

print(describe([1, 2, 3])) # list of 3 items

print(describe("hi"))      # unknown: 'hi'

```

  

### `@functools.cached_property` — compute once, then cache on the instance

  

```python

from functools import cached_property

  

class Dataset:

    def __init__(self, rows):

        self.rows = rows

  

    @cached_property

    def stats(self):

        print("computing…")           # runs only the first time

        return {"count": len(self.rows), "sum": sum(self.rows)}

  

d = Dataset([1, 2, 3])

print(d.stats)   # computing…  -> {'count': 3, 'sum': 6}

print(d.stats)   # {'count': 3, 'sum': 6}   (cached, no recompute)

```

  

Unlike `@property`, `cached_property` stores the result in the instance `__dict__` and

never recomputes. (Incompatible with `__slots__`, since it needs an instance dict.)

## 2.11 `@contextmanager` — context managers without the class

  

Remember the `Timer` class with `__enter__`/`__exit__` from 1.8? `contextlib` lets you

write the same thing as a single generator function:

  

```python

from contextlib import contextmanager

import time

  

@contextmanager

def timer(label="block"):

    start = time.perf_counter()

    try:

        yield                        # everything before yield = __enter__

    finally:

        elapsed = time.perf_counter() - start   # after yield = __exit__

        print(f"{label} took {elapsed*1000:.2f} ms")

  

with timer("loop"):

    sum(range(1_000_000))

# loop took ~xx ms

```

  

The code before `yield` is setup (`__enter__`); the `finally` block after it is teardown

(`__exit__`). Anything you `yield` becomes the `as` value. Much less boilerplate than a

class for simple cases.

## 2.12 How it all works underneath: descriptors (advanced, optional)

  

This section explains the deepest layer — *why* `@property`, `@classmethod`, and methods

themselves work. Skip on a first pass; come back when curious.

  

A **descriptor** is any object defining `__get__` (and optionally `__set__`/

`__delete__`). When such an object is a *class attribute*, Python routes attribute access

through those methods. Properties, methods, `classmethod`, and `staticmethod` are all

descriptors.

  

Here's `property` reimplemented in miniature to demystify it:

  

```python

class my_property:

    def __init__(self, fget):

        self.fget = fget

  

    def __get__(self, obj, objtype=None):

        if obj is None:

            return self                 # accessed on the class, not an instance

        return self.fget(obj)           # call the getter with the instance

  

    def __set__(self, obj, value):

        raise AttributeError("read-only")

  

class Circle:

    def __init__(self, r):

        self.r = r

  

    @my_property                        # area = my_property(area)

    def area(self):

        return 3.14159 * self.r ** 2

  

c = Circle(2)

print(c.area)      # 12.56636 — Python calls my_property.__get__(area_desc, c, Circle)

```

  

Likewise, a plain function is a descriptor: `obj.method` triggers the function's

`__get__`, which returns a **bound method** (the function with `self` pre-filled). That's

the actual machinery behind "the instance is passed as `self`." Descriptors are the

bedrock beneath most of Part 1 and Part 2.

## PART 2 MINI-PROJECT — a validation decorator

  

Write a decorator `validate_types` that checks arguments against the function's type

annotations and raises `TypeError` on mismatch. Then use it.

  

Target behavior:

  

```python

@validate_types

def place_order(symbol: str, qty: int, price: float):

    return f"{qty} {symbol} @ {price}"

  

place_order("INFY", 10, 1500.0)   # works

place_order("INFY", "ten", 1500)  # TypeError

```

  

<details><summary>Solution</summary>

  

```python

import functools

import inspect

  

def validate_types(func):

    sig = inspect.signature(func)

    @functools.wraps(func)

    def wrapper(*args, **kwargs):

        bound = sig.bind(*args, **kwargs)     # map args to parameter names

        bound.apply_defaults()

        for name, value in bound.arguments.items():

            expected = func.__annotations__.get(name)

            if expected and not isinstance(value, expected):

                raise TypeError(

                    f"{name!r} must be {expected.__name__}, "

                    f"got {type(value).__name__}"

                )

        return func(*args, **kwargs)

    return wrapper

  

@validate_types

def place_order(symbol: str, qty: int, price: float):

    return f"{qty} {symbol} @ {price}"

  

print(place_order("INFY", 10, 1500.0))   # 10 INFY @ 1500.0

# place_order("INFY", "ten", 1500)       # TypeError: 'qty' must be int, got str

```

  

This uses `inspect.signature` to map positional/keyword args to parameter names — the

robust way to introspect a function's arguments inside a decorator.

</details>

# CAPSTONE — a mini strategy framework (classes + decorators together)

  

This ties both halves into one small, realistic system. Build a framework where trading

strategies are classes conforming to an interface, auto-registered via a decorator, with

cross-cutting concerns (timing, retry) added declaratively.

  

**Requirements:**

  

1. An abstract `Strategy` (ABC) with abstract `generate_signal(self, price) -> str`.

2. A `@register_strategy` class decorator that adds each strategy to a registry dict

   keyed by class name.

3. A `@timed` method decorator (from 2.4) applied to `generate_signal`.

4. A `Backtester` class that takes a strategy instance and a price series, runs it, and

   returns the list of signals. Support `len()` (number of bars processed) and a

   `win_rate` property (fraction of `"BUY"` signals, as a toy metric).

  

<details><summary>Reference solution</summary>

  

```python

import functools

import time

from abc import ABC, abstractmethod

  

STRATEGY_REGISTRY = {}

  

def register_strategy(cls):

    STRATEGY_REGISTRY[cls.__name__] = cls

    return cls

  

def timed(func):

    @functools.wraps(func)

    def wrapper(*args, **kwargs):

        start = time.perf_counter()

        try:

            return func(*args, **kwargs)

        finally:

            # comment out the print for quiet runs

            _ = (time.perf_counter() - start)

    return wrapper

  
  

class Strategy(ABC):

    @abstractmethod

    def generate_signal(self, price) -> str: ...

  
  

@register_strategy

class Momentum(Strategy):

    def __init__(self, threshold=100):

        self.threshold = threshold

  

    @timed

    def generate_signal(self, price) -> str:

        return "BUY" if price > self.threshold else "SELL"

  
  

@register_strategy

class MeanReversion(Strategy):

    def __init__(self, threshold=100):

        self.threshold = threshold

  

    @timed

    def generate_signal(self, price) -> str:

        return "BUY" if price < self.threshold else "SELL"

  
  

class Backtester:

    def __init__(self, strategy: Strategy, prices):

        self.strategy = strategy

        self.prices = list(prices)

        self.signals = []

  

    def run(self):

        self.signals = [self.strategy.generate_signal(p) for p in self.prices]

        return self.signals

  

    @property

    def win_rate(self):

        if not self.signals:

            return 0.0

        buys = sum(1 for s in self.signals if s == "BUY")

        return buys / len(self.signals)

  

    def __len__(self):

        return len(self.prices)

  

    def __repr__(self):

        return (f"Backtester(strategy={type(self.strategy).__name__}, "

                f"bars={len(self)}, win_rate={self.win_rate:.0%})")

  
  

# --- usage ---

print("Available strategies:", list(STRATEGY_REGISTRY))

# Available strategies: ['Momentum', 'MeanReversion']

  

prices = [95, 101, 99, 105, 110, 90, 102]

  

for name, StratClass in STRATEGY_REGISTRY.items():

    bt = Backtester(StratClass(threshold=100), prices)

    bt.run()

    print(name, bt.signals, f"win_rate={bt.win_rate:.0%}")

    print("  ", repr(bt))

```

  

**What each concept did here:**

  

| Concept | Where it appears |

|---|---|

| ABC | `Strategy` enforces the `generate_signal` contract |

| Inheritance / polymorphism | `Backtester` calls `generate_signal` on any strategy |

| Class decorator | `@register_strategy` for plugin discovery |

| Method decorator + `functools.wraps` | `@timed` on `generate_signal` |

| Properties | `win_rate` as a computed attribute |

| Dunder methods | `__len__`, `__repr__` on `Backtester` |

| Composition | `Backtester` HAS-A strategy |

  

</details>

# Quick-reference cheat sheet

  

**Classes**

  

```python

class C(Base):

    class_attr = 0                      # shared

    def __init__(self, x):

        self.x = x                      # per-instance

    def method(self): ...               # instance method (self)

    @classmethod

    def alt(cls, ...): return cls(...)  # alternate constructor

    @staticmethod

    def helper(...): ...                # namespaced function

    @property

    def y(self): return self._y         # computed / guarded attribute

    @y.setter

    def y(self, v): self._y = v

    def __repr__(self): ...             # always define this

    def __eq__(self, other): ...        # + __hash__ if used in sets/dicts

```

  

**Decorators**

  

```python

# no-arg decorator (2 layers)

def dec(func):

    @functools.wraps(func)

    def wrapper(*a, **k):

        return func(*a, **k)

    return wrapper

  

# decorator with args (3 layers)

def dec(arg):

    def decorator(func):

        @functools.wraps(func)

        def wrapper(*a, **k):

            return func(*a, **k)

        return wrapper

    return decorator

  

# class-based (stateful)

class Dec:

    def __init__(self, func):

        functools.update_wrapper(self, func); self.func = func

    def __call__(self, *a, **k):

        return self.func(*a, **k)

```

  

**Standard-library decorators to reach for:** `functools.wraps`, `functools.cache` /

`lru_cache`, `functools.cached_property`, `functools.singledispatch`,

`functools.total_ordering`, `contextlib.contextmanager`, `dataclasses.dataclass`,

plus the built-in `property`, `classmethod`, `staticmethod`, `abc.abstractmethod`.

# Where to go next

  

- **`dataclasses`** deeper: `field(...)`, `__post_init__`, `frozen`, `slots=True` (3.10+).

- **`typing`**: `Protocol` (structural typing — an alternative to ABCs), `Generic`,

  `TypeVar` for generic classes.

- **`enum.Enum`** for typed constants — cleaner than string signals like `"BUY"`.

- **Descriptors** in depth (the official *Descriptor HowTo Guide*) — the foundation

  beneath properties and methods.

- **Metaclasses** — "classes that create classes." Rarely needed; learn them last, and

  only when you hit a problem that genuinely requires them.

  

Work the exercises until the three-layer decorator pattern and the class/instance/method

distinctions feel automatic. Then the standard library and most frameworks read like

plain English.
