# Phase 7 — CPython Internals & Performance

Understanding the runtime turns "it's slow" into "here's exactly why," and "optimize" into a
disciplined process instead of guesswork.

## 7.1 The execution model

Your source is compiled to **bytecode** — instructions for CPython's evaluation loop. The
`dis` module shows them, which is how you understand what a line actually costs
(**verified output**):

```python
import dis
def f(x): return x * 2 + 1
dis.dis(f)
```
```
  LOAD_FAST   0 (x)      # push local x  (fast — local lookup)
  LOAD_CONST  1 (2)      # push constant 2
  BINARY_OP   5 (*)      # multiply
  LOAD_CONST  2 (1)      # push constant 1
  BINARY_OP   0 (+)      # add
  RETURN_VALUE
```

Notice `LOAD_FAST` for the local `x` — local-variable access is a fast array index, while
globals use a slower dict lookup (`LOAD_GLOBAL`). That single fact is why hoisting a global
into a local inside a hot loop measurably speeds it up. Functions carry a **code object**
(`f.__code__`) holding this bytecode, constants, and variable names; each call creates a
**frame** holding local state.

## 7.2 The memory model

**Reference counting.** Every object tracks how many references point at it; when the count
hits zero, it's freed immediately. `sys.getrefcount` shows it (**verified** — it reads +1
because the argument itself is a temporary reference):

```
after a=[]   : 2      # 'a' + the getrefcount argument
after b=a    : 3      # now two names bind it
after del b  : 2
```

**The cyclic garbage collector.** Refcounting alone can't free a **reference cycle** (`x`
points to `y`, `y` points to `x`) — each keeps the other's count above zero. A separate
generational GC finds and frees cycles (**verified**):

```
alive before gc.collect(): True      # cycle keeps both alive despite `del x, y`
alive after  gc.collect(): False (collected 2 objects)
```

Consequences to know:
- Avoid `__del__` on objects that may be in cycles — historically it complicated collection.
- Break cycles yourself (or use `weakref`) in long-running processes to avoid GC pressure.
- `gc.collect()` forces a collection; `gc.disable()` exists but is rarely wise.

**`weakref`** references an object *without* keeping it alive — essential for caches and
observer patterns that shouldn't prevent cleanup (**verified**: the weakref reads `None`
right after the object is deleted).

**Other memory facts:** small ints and short strings are **interned** (reused singletons);
`__slots__` removes the per-instance `__dict__` for big memory savings; `sys.getsizeof`
measures one object and `tracemalloc` profiles allocations over time (you used it in the
Phase 3 milestone).

## 7.3 The import system

`import x` runs the module **once**, caches it in `sys.modules`, and binds the name. Key
points:
- Re-imports hit the cache — modules are singletons per process.
- **Packages** are directories; `__init__.py` runs on first import; `__all__` controls what
  `from pkg import *` exposes. **Namespace packages** (PEP 420) allow packages with no
  `__init__.py` split across directories.
- `importlib.import_module("name")` imports by string (dynamic/plugin loading).
- **Circular imports** happen when A imports B while B imports A. Fixes: move the import
  inside the function that needs it (deferred), import the *module* not the *name*, restructure
  to remove the cycle, or (for type-only needs) use `if TYPE_CHECKING:` from tutorial 4.

## 7.4 Profiling — measure before you optimize

The cardinal rule: **never optimize on a hunch.** Profile first.

- **`timeit`** — micro-benchmark a small snippet. **Verified contrasts that justify idioms:**
  ```
  "".join(parts) : 0.062s      vs   += in a loop : 0.246s      (~4x)
  'in' set  (200,000 lookups): 0.0044s
  'in' list (200 lookups)    : 0.1297s     <- O(n) scan; 1000x fewer lookups, 30x slower
  ```
  The set-vs-list result is the headline: membership testing is O(1) on a set/dict and O(n)
  on a list. Choosing the right container beats almost any micro-optimization.
- **`cProfile`** — whole-program function-level profiling: `python -m cProfile -s cumtime
  script.py`, or in code with `pstats` to sort/inspect. Shows where time actually goes.
- **`line_profiler`** (`kernprof`) — per-line timing of a hot function.
- **`memory_profiler`** / **`tracemalloc`** — where memory goes.
- **`py-spy`** / **`scalene`** — sampling profilers that attach to a *running* process with no
  code changes; invaluable in production.

## 7.5 Optimization strategy (in order)

1. **Algorithm & data structure** — the biggest wins. An O(n) set lookup vs O(n²) nested
   loop dwarfs any constant-factor tweak (see the benchmark above).
2. **Vectorize** — push loops into NumPy/Polars C code (which also releases the GIL).
3. **Cache** — `functools.lru_cache`/`cache` for pure functions (tutorial 2).
4. **Idiom-level** — `"".join()` over `+=`, comprehensions over manual loops, local names in
   hot loops, avoid needless work.
5. **Go native** — only when profiling proves a hot loop is the bottleneck: `numba` (`@jit`
   for numeric code), **Cython** (compile annotated Python to C), `ctypes`/`cffi` (call
   existing C libraries), or a C extension. Awareness of **PyPy** (a JIT-compiling
   interpreter) rounds this out.

# Phase 8 — Standard-Library Mastery

"Batteries included" is Python's superpower. Experts reach for the stdlib before pip. Tour
these until you know *what exists*; look up details as needed. All demos below are **verified
output**.

## 8.1 Data structures — `collections`, `heapq`, `bisect`, `array`

```python
from collections import Counter, defaultdict, deque
Counter("mississippi").most_common(2)   # [('i', 4), ('s', 4)]
dd = defaultdict(list); dd["a"].append(1)   # auto-creates the list
deque([1,2,3], maxlen=3)                 # append(4) -> [2,3,4] (auto-evicts oldest)
```

- **`Counter`** — tallies with `.most_common()`. **`defaultdict`** — no more "if key missing"
  boilerplate. **`deque`** — O(1) appends/pops at *both* ends, and `maxlen` gives a free ring
  buffer. **`namedtuple`**/**`ChainMap`** round out the module.
- **`heapq`** — a priority queue on a plain list (`heappush`/`heappop`/`heapify`,
  `nlargest`/`nsmallest`). **`bisect`** — binary search & sorted insertion (`insort` keeps a
  list ordered). **`array`** — compact homogeneous numeric arrays.

## 8.2 Records & constants — `dataclasses`, `enum`, `NamedTuple`

```python
from dataclasses import dataclass
@dataclass(frozen=True, slots=True)      # immutable, hashable, compact
class Point:
    x: int; y: int
```

`@dataclass` generates `__init__`/`__repr__`/`__eq__`; options include `frozen` (immutable +
hashable), `slots=True` (3.10, compact), `kw_only`, `order`, `field(default_factory=...)`,
`__post_init__`, and `InitVar`. Reach for it whenever a class is mostly a bundle of fields.

```python
from enum import Enum, IntFlag, StrEnum, auto
class Color(Enum): RED = auto(); GREEN = auto()      # Color.RED.value == 1
class Perm(IntFlag): R=4; W=2; X=1                   # Perm.R | Perm.W  -> value 6
class Mode(StrEnum): LIVE="live"                     # Mode.LIVE == "live"  (a real str)
```

`Enum` for typed constants; `IntFlag`/`Flag` for combinable bit flags; `StrEnum`/`IntEnum`
(3.11) when the member must also *be* a str/int; `@unique` to forbid duplicates.

## 8.3 Numbers & time — `decimal`, `fractions`, `statistics`, `datetime`, `zoneinfo`

The money gotcha every developer must know (**verified**):

```python
0.1 + 0.2 == 0.3                                    # False  (binary float error!)
from decimal import Decimal
Decimal("0.1") + Decimal("0.2") == Decimal("0.3")   # True   (exact decimal arithmetic)
from fractions import Fraction
Fraction(1, 3) * 3                                  # 1      (exact rational)
```

Use **`Decimal`** for money and anything where rounding matters; **`Fraction`** for exact
ratios; **`statistics`** for mean/median/stdev without NumPy. For time, use **`datetime`**
with **`zoneinfo`** (`ZoneInfo("Asia/Kolkata")`) for correct timezone-aware timestamps — never
naive datetimes for anything crossing zones.

## 8.4 Text & data formats — `re`, `json`, `csv`, `pickle`, `sqlite3`, `struct`

- **`re`** — regex: `match`/`search`/`findall`/`finditer`/`sub`, groups and named groups
  `(?P<name>...)`, flags, and **compiled** patterns (`re.compile`) for reuse. Always use raw
  strings (`r"\d+"`).
- **`json`** — `loads`/`dumps` (with `default=` for custom types). **`csv`** — `reader`/
  `DictReader`/`writer`. **`sqlite3`** — a full SQL database in the stdlib (you use it).
  **`struct`** — pack/unpack binary data. **`pickle`** — Python object serialization, but
  **never unpickle untrusted data** (arbitrary code execution).

## 8.5 Files & OS — `pathlib`, `io`, `subprocess`, `shutil`, `tempfile`

```python
from pathlib import Path
p = Path("data") / "trades.csv"          # OS-independent path joining
p.suffix, p.stem, p.exists(), p.read_text()   # rich, object-oriented path ops
```

Prefer **`pathlib.Path`** over `os.path` string-juggling. **`io`** (`StringIO`/`BytesIO`,
buffering), **`shutil`** (copy/move trees), **`tempfile`** (safe temp files), and
**`subprocess`** (`subprocess.run(cmd, capture_output=True, text=True, check=True)`) cover
the OS surface.

## 8.6 Program plumbing — `argparse`, `contextlib`, `copy`, `warnings`

**`argparse`** (CLIs), **`contextlib`** (`contextmanager`, `ExitStack`, `suppress`,
`closing`), **`copy`** (`copy`/`deepcopy`), **`functools`**/**`itertools`**/**`operator`**
(tutorials 2–3), **`weakref`**, and **`logging`** (its own deep-dive in Phase 9). Knowing
these exist saves you from re-implementing them badly.

# Phase 9 — Errors, Robustness & Logging

Expert code fails *clearly* and recovers *gracefully*. Demos below are **verified output**.

## 9.1 The exception model

Catch **specifically**, never bare. Use a **custom hierarchy** so callers can catch at the
right granularity (**verified** — the base type catches all subclasses):

```python
class TradingError(Exception): ...
class InsufficientFunds(TradingError): ...
class InvalidSymbol(TradingError): ...

try:
    raise InsufficientFunds("need 1000 more")
except TradingError as e:            # base catches every subclass
    ...                              # caught InsufficientFunds: need 1000 more
```

`try/except/else/finally`: `else` runs if no exception; `finally` always runs (cleanup).

## 9.2 Exception chaining — preserve the cause

When you catch and re-raise a different exception, chain it so the original isn't lost
(**verified** — `__cause__` holds the `KeyError`):

```python
def load(cfg):
    try:
        return cfg["ratio"]
    except KeyError as e:
        raise InvalidSymbol("config missing 'ratio'") from e   # keep the root cause
```

`raise X from e` sets `__cause__` (shown in the traceback as "The above was the direct cause
…"). Use `raise X from None` to deliberately suppress a noisy inner cause.

## 9.3 Exception groups & `except*` (3.11+)

When multiple things fail at once (concurrent tasks, batch operations), raise an
**`ExceptionGroup`** and handle subsets with **`except*`** (**verified** — it splits the
group by type):

```python
raise ExceptionGroup("batch failed", [InsufficientFunds("A"), InvalidSymbol("X"), ValueError("q")])
# handled as:
except* TradingError as eg:  ...   # ['A', 'X']
except* ValueError as eg:    ...   # ['q']
```

This is what `asyncio.TaskGroup` (tutorial 6) uses to report several task failures together.

## 9.4 Cleanup — context managers & `ExitStack`

Guarantee resource release with `with`. For a *dynamic* number of resources, use
**`ExitStack`** (**verified** — three resources open, then close in reverse order even if the
block raises):

```python
from contextlib import ExitStack
with ExitStack() as stack:
    handles = [stack.enter_context(open(p)) for p in paths]   # any number
    ...   # all closed, reverse order, on exit or exception
```

## 9.5 Logging — done properly

Stop using `print` for anything but scripts. **`logging`** gives levels, destinations, and
structure:

```python
import logging
logger = logging.getLogger(__name__)      # a per-module logger (the standard pattern)

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(name)s %(levelname)s %(message)s",
)

logger.debug("fine detail")     # filtered out below INFO
logger.info("order placed", extra={"symbol": "INFY"})
logger.warning("retrying")
logger.error("failed", exc_info=True)   # include the traceback
```

Principles: create a logger per module with `getLogger(__name__)`; set **levels**
(DEBUG/INFO/WARNING/ERROR/CRITICAL); attach **handlers** (`StreamHandler`, `FileHandler`,
`RotatingFileHandler`) with **formatters**; configure once at the app entry point; let
messages **propagate** up the logger hierarchy; and **never log secrets** (tokens,
passwords, API keys). Use `logger.exception(...)` inside an `except` to log with traceback.

## 9.6 Defensive design & debugging

- **Validate at boundaries** (where external data enters), then trust it internally.
- **Fail fast** — raise early on bad state rather than limping on.
- **`assert` is not for production validation** — it's stripped under `python -O`. Use it for
  internal invariants/tests; raise real exceptions for user-facing checks.
- **Idempotency & retries** — make operations safe to retry (tutorial 2's `@retry`), with
  backoff, for transient failures (network, broker).
- **Debugging**: `breakpoint()` drops into `pdb` (`n`ext, `s`tep, `c`ontinue, `p`rint,
  `w`here); read tracebacks bottom-up (the last line is the actual error); `faulthandler` for
  hard crashes.

# Phase 10 — Engineering Craft

## 10.1 Testing

**`pytest`** is the standard. A tiny but complete example — the module has a **doctest**, and
the tests use **`parametrize`** and a **`hypothesis`** property test:

```python
# money.py
def split_bill(total: int, people: int) -> list[int]:
    """Split `total` into `people` shares differing by at most 1.

    >>> split_bill(100, 3)
    [34, 33, 33]
    >>> sum(split_bill(100, 3))
    100
    """
    if people <= 0:
        raise ValueError("people must be positive")
    base, extra = divmod(total, people)
    return [base + 1] * extra + [base] * (people - extra)
```
```python
# test_money.py
import pytest
from hypothesis import given, strategies as st
from money import split_bill

@pytest.mark.parametrize("total,people", [(100, 3), (10, 2), (7, 7), (0, 4)])
def test_sums_back(total, people):
    assert sum(split_bill(total, people)) == total

def test_rejects_zero_people():
    with pytest.raises(ValueError):
        split_bill(100, 0)

@given(total=st.integers(0, 10_000), people=st.integers(1, 100))
def test_property(total, people):                 # hypothesis generates hundreds of cases
    shares = split_bill(total, people)
    assert sum(shares) == total                   # invariant 1: always sums back
    assert max(shares) - min(shares) <= 1         # invariant 2: fair within 1
```

**Verified results:**
```
pytest      : 6 passed in 0.72s
doctest     : 2 passed and 0 failed
ruff (lint) : All checks passed!
mypy --strict: Success: no issues found
```

The toolkit:
- **`pytest`** — `fixtures` (`@pytest.fixture`, scopes, `conftest.py` for shared ones),
  `parametrize` (one test, many cases), markers, and rich `assert` introspection.
- **Mocking** — `unittest.mock`/`monkeypatch` to replace dependencies (network, time, files).
- **`hypothesis`** — *property-based* testing: you state invariants; it generates hundreds of
  inputs and **shrinks** any failure to a minimal counterexample. Superb for numeric/edge-case
  code (exactly the split above).
- **`doctest`** — examples in docstrings double as tests (and stay accurate).
- **coverage** (`pytest-cov`), **`tox`/`nox`** for multi-version test matrices.

## 10.2 Static quality

- **`ruff`** — an extremely fast linter *and* formatter that replaces black + flake8 + isort.
  `ruff check` (lint) and `ruff format`. (Verified clean above.)
- **`mypy`** / **`pyright`** — static type checking (tutorial 4); aim for `--strict`.
- **`pre-commit`** — run ruff/mypy/tests automatically on every commit so problems never land.

## 10.3 Environments & packaging

- **Virtual environments** isolate dependencies (`python -m venv`, or **`uv`**'s fast envs).
- **`uv`** (fast, modern) or Poetry/PDM manage dependencies and lock files.
- **`pyproject.toml`** is the one config file (PEP 517/518/621): project metadata,
  dependencies, and tool config (ruff, mypy, pytest all read it).
- **Building & publishing**: `python -m build` → wheel/sdist; `twine upload` to PyPI.
- **Entry points** (`[project.scripts]`) create console commands; `pip install -e .` gives an
  editable install for development. Follow **semantic versioning** (MAJOR.MINOR.PATCH).

A minimal `pyproject.toml`:
```toml
[project]
name = "mytool"
version = "0.1.0"
dependencies = ["httpx>=0.27"]

[project.scripts]
mytool = "mytool.cli:main"

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"
```

## 10.4 Version control & design

- **Git fluency**: meaningful commits, branching, rebase, `bisect` (find the commit that
  broke something), hooks.
- **Design & architecture**: Pythonic patterns (strategy via functions/`Protocol`, factory,
  observer, dependency injection by *passing* dependencies rather than hard-coding them);
  **SOLID** adapted to Python; **composition over inheritance** (tutorial 1); `Protocol`-based
  interfaces (tutorial 4); and — the most practical habit — **separate pure logic from I/O**
  so the logic is trivially testable (no mocks needed).
