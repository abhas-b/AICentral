# Phase 1 — The Object & Data Model

*Deep Python Mastery series · Tutorial 1 of the roadmap*

This is where Python stops being "a language you write" and starts being "a language you
extend." The **data model** is the set of hooks — the *dunder* (double-underscore) special
methods — that let your own objects plug into every operator, built-in function, and
syntactic construct Python has. Master this and your classes stop feeling like data bags
and start feeling like native types.

> **Prerequisites:** classes and decorators (the previous two tutorials). You should be
> comfortable with `__init__`, `self`, methods, `@property`, and `@classmethod`.
> **Python:** 3.10+. A few hooks are version-flagged.

---

## The one idea that unlocks everything

Python does not check *types*; it invokes *protocols*. When you write:

```python
len(x)        # Python calls  x.__len__()
x + y         # Python calls  x.__add__(y)
x[3]          # Python calls  x.__getitem__(3)
for i in x:   # Python calls  iter(x) -> x.__iter__()
str(x)        # Python calls  x.__str__()
x == y        # Python calls  x.__eq__(y)
```

Every piece of Python syntax is sugar over a special method. If your object implements the
right dunder, it *becomes* something you can `len()`, add, index, iterate, print, or
compare — indistinguishable from a built-in. This is called **duck typing at the protocol
level**: Python doesn't ask "are you a sequence?", it asks "do you implement `__len__` and
`__getitem__`?"

You almost never call dunders directly (`x.__len__()`). You write the natural syntax
(`len(x)`) and let Python dispatch. Your job as the class author is to *implement* them.

Here's the full landscape, grouped — we'll work through each group:

| Category | Key dunders |
|---|---|
| Representation | `__repr__` `__str__` `__format__` `__bytes__` |
| Truthiness | `__bool__` (falls back to `__len__`) |
| Equality & hashing | `__eq__` `__hash__` |
| Ordering | `__lt__` `__le__` `__gt__` `__ge__` |
| Containers | `__len__` `__getitem__` `__setitem__` `__delitem__` `__contains__` `__iter__` `__reversed__` |
| Callable | `__call__` |
| Attribute access | `__getattr__` `__getattribute__` `__setattr__` `__delattr__` `__dir__` |
| Context managers | `__enter__` `__exit__` |
| Numeric operators | `__add__` `__mul__` … `__radd__` … `__iadd__` … `__neg__` `__abs__` `__index__` |
| Copy & pickle | `__copy__` `__deepcopy__` `__getstate__` `__setstate__` |
| Class creation | `__init_subclass__` `__set_name__` `__class_getitem__` |
| Descriptors | `__get__` `__set__` `__delete__` |

## 1. Representation: `__repr__`, `__str__`, `__format__`

Two audiences need to see your object: **developers** (debugging) and **users** (display).

- `__repr__` → the developer-facing, unambiguous form. Ideally valid Python that could
  recreate the object. Used in the REPL, in containers, and by `repr()`.
- `__str__` → the user-facing, readable form. Used by `print()` and `str()`. Falls back to
  `__repr__` if not defined.
- `__format__` → controls what happens inside f-strings and `format()` with a format spec.

```python
class Money:
    def __init__(self, amount, currency="INR"):
        self.amount = amount
        self.currency = currency

    def __repr__(self):
        # unambiguous; note !r so strings get quoted
        return f"Money({self.amount!r}, {self.currency!r})"

    def __str__(self):
        symbol = {"INR": "₹", "USD": "$"}.get(self.currency, "")
        return f"{symbol}{self.amount:,.2f}"

    def __format__(self, spec):
        # let the caller pass a spec: f"{m:plain}" or a normal numeric spec
        if spec == "plain":
            return f"{self.amount:.2f} {self.currency}"
        if spec == "":
            return str(self)
        # delegate any other spec (e.g. '>12') to the numeric part
        return format(self.amount, spec)


m = Money(1234.5)
print(repr(m))        # Money(1234.5, 'INR')
print(str(m))         # ₹1,234.50
print(m)              # ₹1,234.50            (print uses __str__)
[m]                   # [Money(1234.5, 'INR')]  (containers use __repr__)
print(f"{m}")         # ₹1,234.50            (empty spec -> __str__ path)
print(f"{m:plain}")   # 1234.50 INR          (custom spec)
print(f"{m:>12}")     # delegates to numeric formatting
```

**Rules of thumb**

- **Always define `__repr__`.** A class without one prints as `<Money object at 0x...>`,
  which is useless in logs and tracebacks.
- Define `__str__` only when users need something prettier than the repr.
- `__format__` is optional; define it when your object has meaningful format variants.
- The `!r` conversion in f-strings (`{x!r}`) calls `repr()`; `!s` calls `str()`.

Build a `Duration` class holding a number of seconds. Give it a `__repr__` like

```python
        self.seconds = int(seconds)

    def __repr__(self):

    def __str__(self):
        h, rem = divmod(self.seconds, 3600)
        m, s = divmod(rem, 60)
        parts = []
        if h: parts.append(f"{h}h")
        if m: parts.append(f"{m}m")
        parts.append(f"{s}s")

print(d)                # 1h 1m 1s
print(f"{d:clock}")     # 01:01:01
```

## 2. Truthiness: `__bool__`

`if obj:` calls `bool(obj)` → `obj.__bool__()`. If you don't define it, Python falls back
to `__len__` (nonzero length = truthy); if neither exists, objects are always truthy.

```python
class Cart:
    def __init__(self):
        self.items = []

    def __bool__(self):
        return len(self.items) > 0

c = Cart()
print(bool(c))           # False
c.items.append("book")
print(bool(c))           # True
if c:
    print("cart has items")
```

If `Cart` had defined `__len__` returning `len(self.items)`, you'd get the same truthiness
for free — you rarely need both. Prefer `__len__` when the object is container-like.

## 3. Equality & hashing: `__eq__` and `__hash__`

By default, `==` compares identity (`is`) — two objects are equal only if they're the same
object. Usually you want *value* equality:

```python
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __eq__(self, other):
        if not isinstance(other, Point):
            return NotImplemented          # let the other side try; don't raise
        return (self.x, self.y) == (other.x, other.y)

print(Point(1, 2) == Point(1, 2))    # True
```

**The critical rule about hashing.** The moment you define `__eq__`, Python sets
`__hash__` to `None`, making your object **unhashable** — it can't go in a `set` or be a
`dict` key:

```python
# {Point(1, 2)}   ->  TypeError: unhashable type: 'Point'
```

Why? Because hashability has a contract: **objects that compare equal must have equal
hashes.** If you customize equality, Python can't know your hash is still consistent, so it
disables it to keep you safe. To restore hashability, define `__hash__` yourself — and base
it on the *same* fields your `__eq__` uses:

```python
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __eq__(self, other):
        if not isinstance(other, Point):
            return NotImplemented
        return (self.x, self.y) == (other.x, other.y)

    def __hash__(self):
        return hash((self.x, self.y))     # hash of a tuple of the same fields

p = Point(1, 2)
print({p, Point(1, 2)})                   # {Point(...)} — deduped, one element
```

**Consequences & guidance**

- Return `NotImplemented` (not `False`, not raising) for unknown types — this lets Python
  try `other.__eq__(self)` before giving up.
- Only define `__hash__` for objects that are **immutable in the fields used** — if a field
  changes after the object is placed in a set/dict, lookups break silently.
- Mutable value objects should stay unhashable (that's the safe default Python gives you).
- Frozen dataclasses (`@dataclass(frozen=True)`) generate a correct `__eq__` **and**
  `__hash__` for you — a great shortcut.

## 4. Ordering: `__lt__` and friends

Comparison operators map to `__lt__` (`<`), `__le__` (`<=`), `__gt__` (`>`), `__ge__`
(`>=`). Sorting (`sorted`, `min`, `max`, `list.sort`) needs only `__lt__`. Writing all four
is tedious, so `functools.total_ordering` fills the rest in from `__eq__` + `__lt__`:

```python
from functools import total_ordering

@total_ordering
class SemVer:
    def __init__(self, major, minor, patch):
        self.t = (major, minor, patch)

    def __eq__(self, other):
        if not isinstance(other, SemVer):
            return NotImplemented
        return self.t == other.t

    def __lt__(self, other):
        if not isinstance(other, SemVer):
            return NotImplemented
        return self.t < other.t          # tuples compare lexicographically

    def __repr__(self):
        return "SemVer" + str(self.t)

versions = [SemVer(1, 2, 0), SemVer(1, 0, 5), SemVer(1, 2, 1)]
print(sorted(versions))    # [SemVer(1, 0, 5), SemVer(1, 2, 0), SemVer(1, 2, 1)]
print(max(versions))       # SemVer(1, 2, 1)
print(SemVer(1, 0, 0) < SemVer(2, 0, 0))   # True
```

The **tuple trick** — comparing `(a, b, c)` tuples — is the idiomatic way to get
multi-field ordering right, because tuples already compare element by element.

### Exercise 4

Model a playing `Card` with a rank (2–14, where 11–14 are J/Q/K/A) and a suit. Make cards

## 5. The container protocol

This is the richest and most useful group: make your object behave like a list/dict.

- `__len__` → `len(obj)`
- `__getitem__` → `obj[key]`, and enables iteration + slicing
- `__setitem__` → `obj[key] = value`
- `__delitem__` → `del obj[key]`
- `__contains__` → `x in obj`
- `__iter__` → explicit iteration
- `__reversed__` → `reversed(obj)`

```python
class Playlist:
    def __init__(self, songs=()):
        self._songs = list(songs)

    def __len__(self):
        return len(self._songs)

    def __getitem__(self, index):
        return self._songs[index]        # supports int AND slice automatically here

    def __setitem__(self, index, value):
        self._songs[index] = value

    def __delitem__(self, index):
        del self._songs[index]

    def __contains__(self, song):
        return song in self._songs

    def __iter__(self):
        return iter(self._songs)

    def __repr__(self):
        return f"Playlist({self._songs})"


pl = Playlist(["a", "b", "c", "d"])
print(len(pl))          # 4
print(pl[1])            # b
print(pl[1:3])          # ['b', 'c']   (slicing works because list handles it)
pl[0] = "z"
del pl[3]
print("z" in pl)        # True
for s in pl: print(s, end=" ")   # z b c
print()
print(list(reversed(pl)))        # ['c', 'b', 'z']  (falls back to __len__+__getitem__)
```

### Handling slices explicitly

When your storage isn't a list, `__getitem__` receives an `int` or a `slice` object and you
must handle both. A `slice` has `.start`, `.stop`, `.step`, and a handy `.indices(len)`
helper:

```python
class Range:
    """A lazy integer range that returns a new Range when sliced."""
    def __init__(self, start, stop, step=1):
        self.start, self.stop, self.step = start, stop, step

    def _values(self):
        return list(range(self.start, self.stop, self.step))

    def __len__(self):
        return len(self._values())

    def __getitem__(self, index):
        if isinstance(index, slice):
            # translate the slice against our length, return a new Range-like list
            return self._values()[index]
        if isinstance(index, int):
            return self._values()[index]
        raise TypeError(f"indices must be int or slice, not {type(index).__name__}")

r = Range(0, 10, 2)     # 0,2,4,6,8
print(r[2])             # 4
print(r[1:3])           # [2, 4]
```

### The professional way: subclass `collections.abc`

Implementing every container method by hand is error-prone. The abstract base classes in
`collections.abc` give you a pile of methods **for free** once you implement a small
required set:

- Implement `__len__` + `__getitem__` → subclass `Sequence` → you *automatically* get
  `__contains__`, `__iter__`, `__reversed__`, `index()`, and `count()`.
- Implement `__getitem__/__setitem__/__delitem__/__len__/insert` → `MutableSequence` gives
  you `append`, `extend`, `pop`, `remove`, `__iadd__`, etc.
- Similar mixins exist for `Mapping`, `MutableMapping`, `Set`, `MutableSet`.

```python
from collections.abc import Sequence

class Playlist(Sequence):            # note: inherit from Sequence
    def __init__(self, songs=()):
        self._songs = list(songs)

    def __len__(self):
        return len(self._songs)

    def __getitem__(self, index):
        return self._songs[index]

pl = Playlist(["a", "b", "c"])
print("b" in pl)             # True   — __contains__ provided by Sequence
print(list(reversed(pl)))    # ['c', 'b', 'a']   — __reversed__ provided
print(pl.index("c"))         # 2      — index() provided
print(pl.count("a"))         # 1      — count() provided
```

The ABC also **enforces** correctness: if you forget a required method, instantiation
fails loudly. Use `collections.abc` whenever you build a real container — don't reinvent it.

### Exercise 5

Build a fixed-size `CircularBuffer(capacity)` (a.k.a. ring buffer): `push(x)` adds an item,
overwriting the oldest once full. Support `len()`, iteration in insertion order, indexing,
and a good `repr`.

<details><summary>Solution</summary>

```python
from collections import deque
from collections.abc import Sequence

class CircularBuffer(Sequence):
    def __init__(self, capacity):
        self.capacity = capacity
        self._data = deque(maxlen=capacity)   # deque with maxlen auto-evicts oldest

    def push(self, item):
        self._data.append(item)

    def __len__(self):
        return len(self._data)

    def __getitem__(self, index):
        # deque doesn't slice; convert for slice support
        if isinstance(index, slice):
            return list(self._data)[index]
        return self._data[index]

    def __repr__(self):
        return f"CircularBuffer(capacity={self.capacity}, items={list(self._data)})"

buf = CircularBuffer(3)
for x in [1, 2, 3, 4, 5]:
    buf.push(x)
print(buf)              # CircularBuffer(capacity=3, items=[3, 4, 5])
print(len(buf))         # 3
print(buf[0], buf[-1])  # 3 5
print(3 in buf)         # True   (free from Sequence)
print(list(buf))        # [3, 4, 5]  (free iteration)
```
</details>

## 6. Callables: `__call__`

An object whose class defines `__call__` can be *called like a function*. This is how you
build stateful "functions" and — as you saw — class-based decorators.

```python
class Accumulator:
    def __init__(self):
        self.total = 0

    def __call__(self, x):
        self.total += x
        return self.total

acc = Accumulator()
print(acc(10))       # 10
print(acc(5))        # 15
print(callable(acc)) # True
```

Reach for `__call__` when you want function-like ergonomics but need to carry state or
configuration between calls (running totals, memoizers, parametrized strategies).

## 7. Attribute access hooks

You can intercept attribute reads and writes. This powers proxies, lazy loading, and
attribute-style access to dynamic data.

- `__getattr__(self, name)` — called **only when normal lookup fails** (attribute not found
  the usual way). The safe, common hook.
- `__getattribute__(self, name)` — called on **every** attribute access. Powerful but
  dangerous (easy to cause infinite recursion); rarely needed.
- `__setattr__(self, name, value)` — called on **every** assignment `obj.x = ...`.
- `__delattr__(self, name)` — called on `del obj.x`.
- `__dir__(self)` — customizes `dir(obj)`.

```python
class DotDict:
    """Access dict keys as attributes: d.name instead of d['name']."""
    def __init__(self, data):
        # use the base __setattr__ to avoid triggering our own override
        object.__setattr__(self, "_data", data)

    def __getattr__(self, name):
        # only called if 'name' wasn't found normally
        try:
            return self._data[name]
        except KeyError:
            raise AttributeError(name) from None

    def __setattr__(self, name, value):
        self._data[name] = value

d = DotDict({"symbol": "INFY", "price": 1500})
print(d.symbol)      # INFY
d.qty = 10           # goes into the dict via __setattr__
print(d._data)       # {'symbol': 'INFY', 'price': 1500, 'qty': 10}
# d.missing          # AttributeError: missing
```

**The recursion trap:** inside `__getattr__`/`__setattr__`, accessing `self.something`
naively can re-trigger the hook forever. Break the cycle by going through
`object.__getattribute__`/`object.__setattr__` or by touching `self.__dict__` directly (as
we did with `object.__setattr__` above).

### Exercise 7

Build a `LazyConfig` whose values are computed on first access and then cached. Given a dict
of `{name: zero_arg_function}`, `cfg.name` should call the function once, cache the result,
and return the cached value on later accesses.

<details><summary>Solution</summary>

```python
class LazyConfig:
    def __init__(self, providers):
        object.__setattr__(self, "_providers", providers)
        object.__setattr__(self, "_cache", {})

    def __getattr__(self, name):
        if name in self._cache:
            return self._cache[name]
        if name in self._providers:
            value = self._providers[name]()     # compute once
            self._cache[name] = value
            return value
        raise AttributeError(name)

calls = []
cfg = LazyConfig({
    "db": lambda: (calls.append("db"), "connection")[1],
})
print(cfg.db)     # computes -> connection
print(cfg.db)     # cached   -> connection
print(calls)      # ['db']   (provider ran only once)
```
</details>

## 8. Context managers: `__enter__` / `__exit__`

The `with` statement guarantees setup and teardown even if the body raises — the right tool
for resources (files, locks, connections, temporary state).

```python
class Transaction:
    def __init__(self, db):
        self.db = db

    def __enter__(self):
        self.db.setdefault("_log", []).append("BEGIN")
        return self            # bound to the `as` variable

    def __exit__(self, exc_type, exc_val, exc_tb):
        if exc_type is None:
            self.db["_log"].append("COMMIT")
        else:
            self.db["_log"].append(f"ROLLBACK ({exc_type.__name__})")
        # return True to SUPPRESS the exception; False/None to let it propagate
        return False

db = {}
with Transaction(db):
    db["balance"] = 100
print(db["_log"])   # ['BEGIN', 'COMMIT']

try:
    with Transaction(db):
        raise ValueError("boom")
except ValueError:
    pass
print(db["_log"])   # ['BEGIN', 'COMMIT', 'BEGIN', 'ROLLBACK (ValueError)']
```

`__exit__` receives the exception (type, value, traceback) or three `None`s on success.
Returning a truthy value **swallows** the exception — use this deliberately and sparingly.

> For simple cases, `@contextlib.contextmanager` (a generator-based shortcut) is less
> boilerplate — we covered it in the decorators tutorial and will revisit it in Phase 9.

### Exercise 8

Write a context manager `temporary` that sets an attribute on an object to a new value
inside the block and restores the original value on exit (even if an exception is raised).

<details><summary>Solution</summary>

```python
class temporary:
    def __init__(self, obj, attr, value):
        self.obj, self.attr, self.value = obj, attr, value

    def __enter__(self):
        self.original = getattr(self.obj, self.attr)
        setattr(self.obj, self.attr, self.value)
        return self.obj

    def __exit__(self, *exc):
        setattr(self.obj, self.attr, self.original)   # always restores
        return False

class S: level = "INFO"

with temporary(S, "level", "DEBUG"):
    print(S.level)     # DEBUG
print(S.level)         # INFO  (restored)
```

## 9. Numeric & operator protocol

Make your objects do arithmetic. Each operator has a method, a **reflected** version
(`__r*__`, tried when the left operand doesn't know how), and an **in-place** version
(`__i*__`, for `+=` etc.).

```python
class Vector2D:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __add__(self, other):                 # self + other
        if isinstance(other, Vector2D):
            return Vector2D(self.x + other.x, self.y + other.y)
        return NotImplemented

    def __sub__(self, other):
        if isinstance(other, Vector2D):
            return Vector2D(self.x - other.x, self.y - other.y)
        return NotImplemented

    def __mul__(self, scalar):                # self * scalar
        if isinstance(scalar, (int, float)):
            return Vector2D(self.x * scalar, self.y * scalar)
        return NotImplemented

    def __rmul__(self, scalar):               # scalar * self  (reflected)
        return self * scalar

    def __neg__(self):                        # -self
        return Vector2D(-self.x, -self.y)

    def __abs__(self):                        # abs(self) -> magnitude
        return (self.x ** 2 + self.y ** 2) ** 0.5

    def __eq__(self, other):
        return isinstance(other, Vector2D) and (self.x, self.y) == (other.x, other.y)

    def __repr__(self):
        return f"Vector2D({self.x}, {self.y})"


v = Vector2D(3, 4)
print(v + Vector2D(1, 1))   # Vector2D(4, 5)
print(v * 2)                # Vector2D(6, 8)
print(3 * v)                # Vector2D(9, 12)   (uses __rmul__)
print(-v)                   # Vector2D(-3, -4)
print(abs(v))               # 5.0
```

**Why reflected methods matter:** in `3 * v`, Python first tries `int.__mul__(3, v)`, which
returns `NotImplemented` (an int doesn't know how to multiply by a `Vector2D`). Python then
tries `v.__rmul__(3)`. Without `__rmul__`, `3 * v` would raise `TypeError`.

Related dunders worth knowing: `__truediv__` `__floordiv__` `__mod__` `__pow__`
`__matmul__` (`@`), their `__r*__` and `__i*__` variants, and `__round__`, `__floor__`,
`__ceil__`, and `__index__` (lets your object be used where an integer index is required,
e.g. `list[obj]` or `hex(obj)`).

### Exercise 9

Extend `Vector2D` with a `dot(other)` method and support `v @ other` (matrix-mul operator)
as the dot product via `__matmul__`. Return `NotImplemented` for bad types.

<details><summary>Solution</summary>

```python
class Vector2D:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def dot(self, other):
        return self.x * other.x + self.y * other.y

    def __matmul__(self, other):
        if isinstance(other, Vector2D):
            return self.dot(other)
        return NotImplemented

    def __repr__(self):
        return f"Vector2D({self.x}, {self.y})"

print(Vector2D(1, 2) @ Vector2D(3, 4))   # 11   (1*3 + 2*4)
```
</details>

## 10. Copy & pickle hooks (brief)

Control how your object is duplicated or serialized:

- `__copy__` / `__deepcopy__` — customize `copy.copy()` / `copy.deepcopy()`.
- `__getstate__` / `__setstate__` — customize pickling (e.g. drop an open file handle
  before pickling, reopen on load).

You'll rarely need these until you serialize complex objects, but know they exist — the
default behavior (copying/pickling `__dict__`) is usually enough.

```python
import copy

class Node:
    def __init__(self, value, children=None):
        self.value = value
        self.children = children or []

n = Node(1, [Node(2), Node(3)])
shallow = copy.copy(n)       # shares the same children list
deep = copy.deepcopy(n)      # fully independent tree
```

## 11. Class-creation hooks (modern & powerful)

These fire when a *class* is defined or when descriptors are attached — the machinery behind
ORMs, plugin systems, and validation libraries.

### `__init_subclass__` — run code whenever a subclass is created

A lightweight alternative to metaclasses. Great for auto-registration:

```python
class Plugin:
    registry = {}

    def __init_subclass__(cls, /, key=None, **kwargs):
        super().__init_subclass__(**kwargs)
        name = key or cls.__name__.lower()
        Plugin.registry[name] = cls        # every subclass registers itself

class CsvLoader(Plugin, key="csv"): ...
class JsonLoader(Plugin): ...

print(Plugin.registry)
# {'csv': <class 'CsvLoader'>, 'jsonloader': <class 'JsonLoader'>}
```

`__init_subclass__` is implicitly a classmethod and receives keyword arguments passed in the
class definition (`key="csv"`). No metaclass required.

### `__set_name__` — descriptors that learn their own name

When a descriptor is assigned as a class attribute, Python calls its `__set_name__` with the
owning class and the attribute name — so the descriptor knows what it's called:

```python
class Field:
    def __set_name__(self, owner, name):
        self.name = name                       # learns it's called "price", etc.
        self.private = f"_{name}"

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return getattr(obj, self.private, None)

    def __set__(self, obj, value):
        if value < 0:
            raise ValueError(f"{self.name} must be non-negative")
        setattr(obj, self.private, value)

class Product:
    price = Field()        # __set_name__ fires here, learns name == "price"
    qty = Field()

p = Product()
p.price = 100
print(p.price)             # 100
# p.qty = -1               # ValueError: qty must be non-negative
```

This is a preview of **descriptors** (next), and exactly how validation frameworks bind
field names automatically.

### `__class_getitem__` — makes `MyClass[int]` work

This is what lets you write `list[int]` or your own `Stack[int]`. You rarely implement it
directly (typing's `Generic` handles it), but now you know why subscripting a class works.

## 12. Descriptors (introduction)

A **descriptor** is any object defining `__get__` (and optionally `__set__`/`__delete__`).
When placed as a *class attribute*, it intercepts access to that attribute on instances.
Descriptors are the deep mechanism beneath `property`, methods, `classmethod`, and
`staticmethod` — all of them are descriptors.

```python
class Positive:
    """A reusable descriptor enforcing a positive number."""
    def __set_name__(self, owner, name):
        self._name = f"_{name}"

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return getattr(obj, self._name)

    def __set__(self, obj, value):
        if value <= 0:
            raise ValueError("must be positive")
        setattr(obj, self._name, value)

class Circle:
    radius = Positive()          # one reusable validator, usable on many classes

    def __init__(self, radius):
        self.radius = radius     # routed through Positive.__set__

c = Circle(5)
print(c.radius)      # 5
# Circle(-1)         # ValueError: must be positive
```

The key insight: `@property` gives you *one* validated attribute; a **descriptor class**
gives you a *reusable* validator you can drop onto any number of attributes and classes —
DRY validation. **Data descriptors** (those with `__set__`/`__delete__`) take precedence
over instance `__dict__`; **non-data descriptors** (only `__get__`) don't. That precedence
rule is what makes methods and properties behave correctly. We go deep on this in **Phase 5
(Metaprogramming)**.

## 13. `__slots__` — fixing the attribute set

By default each instance carries a `__dict__` for arbitrary attributes — flexible but
memory-heavy and typo-friendly. `__slots__` replaces it with a fixed, compact layout:

```python
class Tick:
    __slots__ = ("timestamp", "price", "volume")   # no per-instance __dict__

    def __init__(self, timestamp, price, volume):
        self.timestamp = timestamp
        self.price = price
        self.volume = volume

t = Tick(1_700_000_000, 1500.0, 250)
# t.symbol = "INFY"    # AttributeError — 'symbol' isn't a slot (typos caught!)
```

**Benefits:** much less memory per instance (matters when you create millions — tick/bar
objects), faster attribute access, and typo protection. **Costs:** no dynamic attributes,
some care needed with inheritance and with tools expecting `__dict__`. Use it for small,
numerous, fixed-shape objects; skip it for general classes.

## Milestone Project — build a `TimeSeries` type

Bring the whole data model together. Build an **immutable, hashable `TimeSeries`**: an
ordered sequence of `(timestamp, value)` points that behaves like a first-class Python
type. Requirements:

1. Construct from pairs; store immutably. Validate timestamps are sorted ascending.
2. **Container protocol**: `len()`, integer indexing returns a `(ts, value)` tuple, **slicing
   returns a new `TimeSeries`**, iteration, membership (`ts in series`).
3. **Representation**: a clean `__repr__` and a `__str__` summary.
4. **Equality & hashing**: value equality; hashable (it's immutable) so it can be a dict key.
5. **Arithmetic**: `series + series` adds values element-wise (only if timestamps align);
   `series * scalar` and `scalar * series` scale the values.
6. Verify it satisfies `collections.abc.Sequence`.

Try it yourself first. Reference solution below.

<details><summary>Reference solution</summary>

```python
from collections.abc import Sequence

class TimeSeries(Sequence):
    __slots__ = ("_ts", "_vals")           # immutable + compact

    def __init__(self, points):
        pts = list(points)
        ts = tuple(t for t, _ in pts)
        vals = tuple(v for _, v in pts)
        if list(ts) != sorted(ts):
            raise ValueError("timestamps must be ascending")
        # store on slots; object.__setattr__ so we could even make it frozen-like
        object.__setattr__(self, "_ts", ts)
        object.__setattr__(self, "_vals", vals)

    # ---- container protocol ----
    def __len__(self):
        return len(self._ts)

    def __getitem__(self, index):
        if isinstance(index, slice):
            # slicing returns a NEW TimeSeries
            pairs = list(zip(self._ts, self._vals))[index]
            return TimeSeries(pairs)
        if isinstance(index, int):
            return (self._ts[index], self._vals[index])
        raise TypeError(f"index must be int or slice, not {type(index).__name__}")

    def __contains__(self, timestamp):
        return timestamp in self._ts

    # (Sequence mixin provides __iter__, __reversed__, index, count for free,
    #  but iterating yields (ts, value) tuples via our __getitem__)

    # ---- representation ----
    def __repr__(self):
        pairs = list(zip(self._ts, self._vals))
        return f"TimeSeries({pairs})"

    def __str__(self):
        if not self._ts:
            return "TimeSeries(empty)"
        return (f"TimeSeries[{len(self)} points, "
                f"{self._ts[0]}..{self._ts[-1]}]")

    # ---- equality & hashing ----
    def __eq__(self, other):
        if not isinstance(other, TimeSeries):
            return NotImplemented
        return self._ts == other._ts and self._vals == other._vals

    def __hash__(self):
        return hash((self._ts, self._vals))    # tuples are hashable -> we are too

    # ---- arithmetic ----
    def __add__(self, other):
        if not isinstance(other, TimeSeries):
            return NotImplemented
        if self._ts != other._ts:
            raise ValueError("timestamps must align to add series")
        summed = [a + b for a, b in zip(self._vals, other._vals)]
        return TimeSeries(zip(self._ts, summed))

    def __mul__(self, scalar):
        if not isinstance(scalar, (int, float)):
            return NotImplemented
        return TimeSeries(zip(self._ts, (v * scalar for v in self._vals)))

    def __rmul__(self, scalar):
        return self * scalar


# ---- exercise the type ----
a = TimeSeries([(1, 100.0), (2, 101.0), (3, 102.0)])
b = TimeSeries([(1, 1.0), (2, 2.0), (3, 3.0)])

print(len(a))            # 3
print(a[1])              # (2, 101.0)
print(a[1:])             # TimeSeries([(2, 101.0), (3, 102.0)])   (new series)
print(2 in a)            # True
print(str(a))            # TimeSeries[3 points, 1..3]
print(a == TimeSeries([(1, 100.0), (2, 101.0), (3, 102.0)]))  # True
print(a + b)             # TimeSeries([(1, 101.0), (2, 103.0), (3, 105.0)])
print(a * 2)             # TimeSeries([(1, 200.0), (2, 202.0), (3, 204.0)])
print(3 * b)             # TimeSeries([(1, 3.0), (2, 6.0), (3, 9.0)])
print({a: "series A"}[a])   # 'series A'   — hashable, usable as a dict key

# verify the protocol
from collections.abc import Sequence
print(isinstance(a, Sequence))   # True
print(list(reversed(a)))         # [(3, 102.0), (2, 101.0), (1, 100.0)]  (free mixin)
```

**What each concept did:**

| Protocol | Where |
|---|---|
| Container | `__len__`, `__getitem__` (int + slice), `__contains__` |
| `collections.abc` mixins | `__iter__`, `__reversed__`, `index`, `count` for free |
| Representation | `__repr__` (round-trippable), `__str__` (summary) |
| Equality & hashing | value `__eq__` + tuple-based `__hash__` → dict key |
| Numeric protocol | `__add__` (aligned), `__mul__`/`__rmul__` (scalar) |
| Memory discipline | `__slots__` for compact, immutable-ish instances |
