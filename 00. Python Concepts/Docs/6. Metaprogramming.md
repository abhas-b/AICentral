# Phase 5 — Metaprogramming

*Deep Python Mastery series · Tutorial 5 of the roadmap*

Metaprogramming is code that manipulates code — classes that build classes, attributes that
run logic, objects that inspect themselves. It's the machinery beneath every framework you
use: Django models, SQLAlchemy, Pydantic, dataclasses, and pytest are all built from the
tools in this phase. Once you understand descriptors, `__init_subclass__`, and metaclasses,
those libraries stop being magic and become readable. Every mechanism below was **run** —
the precedence demos, the mini re-implementations, and the milestone ORM all show real
output.

> **Prerequisites:** the data model (tutorial 1), decorators (tutorial 2), and the type
> system (tutorial 4 — Protocols and typed fields connect directly here).
> **Python:** 3.10+.

---

## The metaprogramming toolkit

You already have one leg of the "trinity" — decorators (functions/classes that transform
functions/classes). This phase adds the other two plus reflection:

1. **Descriptors** — objects that control what happens when an attribute is read/written.
2. **Metaclasses** — the type of a class; they run when a class is *defined*.
3. **Reflection** — inspecting and manipulating objects/code at runtime.

The golden rule up front: **reach for the lightest tool that works.** Most jobs people
think need a metaclass are better done with a class decorator or `__init_subclass__`.
Metaclasses are the tool of last resort.

## 1. Descriptors — attributes with behavior

A **descriptor** is any object, stored as a *class attribute*, that defines at least one of
`__get__`, `__set__`, `__delete__`. When you access that attribute on an instance, Python
routes the access through those methods instead of returning a plain value.

```python
class Descriptor:
    def __get__(self, obj, objtype=None): ...   # obj.attr        (read)
    def __set__(self, obj, value): ...          # obj.attr = value (write)
    def __delete__(self, obj): ...              # del obj.attr     (delete)
```

`__get__` receives `obj` (the instance, or `None` when accessed on the class) and `objtype`
(the class). This is how `property`, methods, `classmethod`, and `staticmethod` all work —
they're descriptors.

### `__set_name__` — a descriptor learns its own name

When a descriptor is assigned in a class body, Python calls `__set_name__(owner, name)`, so
the descriptor knows the attribute name it was bound to — essential for storing per-instance
data:

```python
class Field:
    def __set_name__(self, owner, name):
        self.name = name                # learns it's called "price", "qty", ...
        self.storage = f"_{name}"

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return getattr(obj, self.storage)

    def __set__(self, obj, value):
        setattr(obj, self.storage, value)
```

### Data vs non-data descriptors — the precedence rule that explains everything

This is the single most important (and most misunderstood) rule in the object model:

- A **data descriptor** defines `__set__` and/or `__delete__`. It takes **precedence over the
  instance `__dict__`.**
- A **non-data descriptor** defines only `__get__`. The **instance `__dict__` takes
  precedence over it.**

The full lookup order for `instance.attr` is:

```
data descriptor on the class  >  instance __dict__  >  non-data descriptor  >  class attribute
```

Why this matters, demonstrated (**verified output**):

```python
class WithProperty:
    @property                          # property defines __set__ -> DATA descriptor
    def x(self):
        return "property value"

w = WithProperty()
w.__dict__["x"] = "instance value"     # inject straight into the instance dict
print(w.x)                             # -> property value   (data descriptor WINS)

class WithMethod:
    def m(self):                       # a function -> NON-data descriptor (only __get__)
        return "method value"

wm = WithMethod()
wm.__dict__["m"] = lambda: "instance shadow"
print(wm.m())                          # -> instance shadow  (instance dict wins)
```

This explains two everyday facts at once: you **can** shadow a method by assigning an
instance attribute of the same name (methods are non-data descriptors), but you **cannot**
shadow a `property` that way (it's a data descriptor). The precedence rule *is* the
explanation.

### Proof that methods, `staticmethod`, `classmethod` are all descriptors

A plain function is a non-data descriptor whose `__get__` returns a **bound method**
(the function with `self` pre-filled) — that's the actual mechanism behind "the instance is
passed as `self`" (**verified**):

```python
def f(self):
    return f"bound to {self}"

class C: pass
c = C()
bound = f.__get__(c, C)      # this is what `c.f` does under the hood
print(type(bound).__name__)  # -> method
```

And `staticmethod`/`classmethod` are one-line descriptors (**verified re-implementations**):

```python
class my_staticmethod:
    def __init__(self, fn): self.fn = fn
    def __get__(self, obj, objtype=None):
        return self.fn                       # no binding at all

class my_classmethod:
    def __init__(self, fn): self.fn = fn
    def __get__(self, obj, objtype=None):
        import functools
        return functools.partial(self.fn, objtype)   # bind the class, not the instance

class Demo:
    @my_staticmethod
    def s(a, b): return a + b
    @my_classmethod
    def cls_name(cls): return cls.__name__

print(Demo.s(2, 3))       # 5    — staticmethod: called plainly
print(Demo.cls_name())    # Demo — classmethod: cls injected
```

Internalize this: **the entire "methods, properties, class/static methods" surface is
descriptors.** Once you see that, the object model has no more mysteries.

### Why a descriptor beats `@property` for reuse

`@property` gives you *one* validated attribute and you rewrite the getter/setter for each.
A **descriptor class** is a *reusable* validator you drop onto any number of attributes and
classes — DRY. This is exactly what the milestone builds.

### Exercise 1

Write a reusable `Positive` descriptor that rejects non-positive numbers on assignment. Use
it for two attributes on one class and confirm each validates independently.

<details><summary>Solution</summary>

```python
class Positive:
    def __set_name__(self, owner, name):
        self.storage = f"_{name}"
        self.name = name

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return getattr(obj, self.storage)

    def __set__(self, obj, value):
        if value <= 0:
            raise ValueError(f"{self.name} must be positive")
        setattr(obj, self.storage, value)

class Order:
    qty = Positive()
    price = Positive()
    def __init__(self, qty, price):
        self.qty = qty
        self.price = price

o = Order(10, 1500)
print(o.qty, o.price)     # 10 1500
# Order(-1, 1500)         # ValueError: qty must be positive
# o.price = 0             # ValueError: price must be positive
```

## 2. Dynamic attribute access

Beyond descriptors (which are per-attribute), you can intercept attribute access at the
*object* level.

- `__getattr__(self, name)` — called **only when normal lookup fails**. Safe, common.
- `__getattribute__(self, name)` — called on **every** access. Powerful and dangerous
  (recursion-prone); rarely needed.
- `__setattr__(self, name, value)` — called on **every** assignment.
- `__delattr__(self, name)` — called on `del`.

```python
class Proxy:
    """Forward unknown attribute access to a wrapped object, logging as we go."""
    def __init__(self, target):
        object.__setattr__(self, "_target", target)   # avoid our own __setattr__

    def __getattr__(self, name):
        # only reached for names not found normally -> delegate to the target
        print(f"[proxy] get {name}")
        return getattr(self._target, name)

    def __setattr__(self, name, value):
        print(f"[proxy] set {name}={value!r}")
        setattr(self._target, name, value)

class Engine:
    def start(self): return "vroom"

p = Proxy(Engine())
print(p.start())     # [proxy] get start  ->  vroom
p.rpm = 3000         # [proxy] set rpm=3000
```

**The recursion trap** (worth repeating from tutorial 1): inside `__setattr__`/`__getattr__`,
touching `self.x` naively re-triggers the hook forever. Break the cycle with
`object.__setattr__(self, ...)`, `object.__getattribute__(self, ...)`, or by writing to
`self.__dict__` directly.

**`__getattr__` vs `__getattribute__`:** prefer `__getattr__` — it fires only on misses, so
normal attributes work at full speed and you can't easily recurse. Reach for
`__getattribute__` only when you must intercept *every* access (e.g. a strict sandbox), and
delegate to `super().__getattribute__(name)` to do the real lookup.

**`__slots__` interaction:** a class with `__slots__` has no instance `__dict__`, so
attribute storage goes through slot descriptors (yes — slots are implemented as data
descriptors too). `__getattr__` still works for genuinely missing names.

## 3. Class-creation hooks & metaclasses

Now we manipulate *classes* as they're built.

### `__init_subclass__` — the modern, lightweight hook

Defined on a base class, `__init_subclass__` runs **once for each subclass** at definition
time. It handles most "do something when a class is created" needs without a metaclass:

```python
class Plugin:
    registry = {}

    def __init_subclass__(cls, /, key=None, **kwargs):
        super().__init_subclass__(**kwargs)
        cls.key = key or cls.__name__.lower()
        Plugin.registry[cls.key] = cls        # auto-register every subclass

class CsvLoader(Plugin, key="csv"): ...
class JsonLoader(Plugin): ...

print(Plugin.registry)   # {'csv': CsvLoader, 'jsonloader': JsonLoader}
```

It's implicitly a classmethod, receives keyword arguments from the class definition
(`key="csv"`), and — crucially — runs *after* `__set_name__` has fired on all descriptors,
so it can inspect the class's fields. That ordering is what makes the milestone work.

### Metaclasses — the type of a type

Every class is an instance of a **metaclass** (normally `type`). Just as an object is created
by its class, a class is created by its metaclass. You can see and use this directly:

```python
class Foo: pass
print(type(Foo))          # <class 'type'>  — Foo is an instance of type
print(type(type(Foo)))    # <class 'type'>  — type is its own metaclass

# type() with THREE arguments creates a class dynamically:
Bar = type("Bar", (object,), {"greet": lambda self: "hi"})
print(Bar().greet())      # hi   — a class built at runtime, no `class` statement
```

A custom metaclass subclasses `type` and overrides `__new__` (build the class object) or
`__init__` (initialize it). It's the most powerful class hook — it can rewrite the class's
namespace, enforce rules, register it, or inject members:

```python
class Enforcer(type):
    """A metaclass that forbids method names starting with an underscore-digit, say."""
    def __new__(mcls, name, bases, namespace, **kwargs):
        for attr in namespace:
            if attr.startswith("__") and attr.endswith("__"):
                continue
            if attr != attr.lower():
                raise TypeError(f"{name}.{attr}: use snake_case")
        return super().__new__(mcls, name, bases, namespace)

class Good(metaclass=Enforcer):
    def do_thing(self): ...

# class Bad(metaclass=Enforcer):
#     def DoThing(self): ...        # TypeError at class-definition time
```

Metaclass `__new__` signature: `(mcls, name, bases, namespace, **kwargs)` — the class name,
its base classes, and its body as a dict. Whatever you return *is* the class.

### When to use which

| Need | Tool |
|---|---|
| Modify/validate one class | **class decorator** (simplest) |
| React to each subclass | **`__init_subclass__`** |
| Auto-name descriptors | **`__set_name__`** |
| Deeply control class creation, affect a whole hierarchy, or change the namespace before the class exists | **metaclass** (last resort) |

`@dataclass` is a class decorator. Django/SQLAlchemy models use metaclasses (historically) or
`__init_subclass__` (modern). Prefer the top of that table; drop to a metaclass only when
nothing lighter reaches.

### ABCs are built on a metaclass

`abc.ABC` uses the `ABCMeta` metaclass. Two features worth knowing:

```python
from abc import ABC, abstractmethod

class Reader(ABC):
    @abstractmethod
    def read(self) -> str: ...

# Reader()          # TypeError: can't instantiate abstract class

# Virtual subclasses: register an unrelated class as "counting as" a Reader
class ExternalThing:
    def read(self): return "data"

Reader.register(ExternalThing)          # no inheritance, but now:
print(issubclass(ExternalThing, Reader))  # True
```

`__subclasshook__` lets an ABC define `issubclass` structurally (this is how
`collections.abc.Iterable` recognizes anything with `__iter__` without registration). ABCs
are the standard-library proof that metaclasses earn their keep for real interface machinery.

### Exercise 3

Use `__init_subclass__` to build a `Command` base whose subclasses auto-register in a
`commands` dict keyed by a lowercased class name, and require each subclass to define a
`run` method (raise `TypeError` at definition time if missing).

<details><summary>Solution</summary>

```python
class Command:
    commands = {}

    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        if not callable(getattr(cls, "run", None)):
            raise TypeError(f"{cls.__name__} must define run()")
        Command.commands[cls.__name__.lower()] = cls

class Deploy(Command):
    def run(self): return "deploying"

print(Command.commands)      # {'deploy': <class 'Deploy'>}
# class Broken(Command):     # TypeError: Broken must define run()
#     pass
```
</details>

## 4. Reflection & introspection

Inspecting and manipulating objects at runtime.

### The built-ins

```python
class Obj:
    def __init__(self):
        self.a = 1
        self.b = 2
    def method(self): ...

o = Obj()
print(getattr(o, "a"))            # 1        — dynamic attribute read
setattr(o, "c", 3)                # dynamic write
print(hasattr(o, "c"))            # True
delattr(o, "c")                   # dynamic delete
print(vars(o))                    # {'a': 1, 'b': 2}   — the instance __dict__
print(type(o).__name__)           # Obj
print(isinstance(o, Obj))         # True
print([n for n in dir(o) if not n.startswith("_")])   # ['a', 'b', 'method']
```

`getattr`/`setattr`/`hasattr` with computed names power dispatch, serialization, and plugin
systems. `vars(obj)` returns `__dict__`; `dir(obj)` lists all accessible names.

### The `inspect` module — deep introspection

```python
import inspect

def trade(symbol: str, qty: int = 1, *, price: float) -> str:
    "Place a trade."
    return f"{qty} {symbol} @ {price}"

sig = inspect.signature(trade)
print(sig)                                   # (symbol: str, qty: int = 1, *, price: float) -> str
print(inspect.getdoc(trade))                 # Place a trade.
print([n for n, _ in inspect.getmembers(trade, callable)][:0])  # inspect callables/members
# inspect.getsource(trade)                   # the function's source text
# inspect.stack()                            # the current call stack (frames)
```

`inspect` gives you signatures (used by your Phase 2/4 decorators), source code, class
members, and even stack frames. It's how tools like pytest discover fixtures and how
debuggers walk the stack.

## 5. Code as data (use with care)

The deepest level: treating source code itself as manipulable data.

### `eval` / `exec` / `compile` — and why to avoid them

```python
print(eval("2 + 3 * 4"))                 # 14   — evaluate an expression
exec("x = 10\nprint(x)")                 # 10   — execute statements
code = compile("y = 5", "<string>", "exec")   # pre-compile to a code object
```

`eval`/`exec` run arbitrary code. **Never** pass user- or network-supplied strings to them —
it's a remote-code-execution hole. Almost anything you'd reach for them for (dynamic
dispatch, building objects) is better done with dicts, `getattr`, or `functools.partial`.
Legitimate uses are rare (REPLs, template engines, code generators) and always sandbox-aware.

### `ast` — parse and transform code safely

When you genuinely need to analyze or transform code, parse it into an **Abstract Syntax
Tree** instead of string-hacking:

```python
import ast

tree = ast.parse("result = a * 2 + b")
print(ast.dump(tree, indent=2)[:80], "...")   # a structured tree of the code

# ast.literal_eval is the SAFE alternative to eval for data literals:
print(ast.literal_eval("{'a': [1, 2], 'b': (3, 4)}"))   # only parses literals, runs no code
```

`ast.literal_eval` safely parses Python *literals* (numbers, strings, tuples, lists, dicts) —
use it instead of `eval` whenever you're just reading data. Full `ast` walking/transforming
powers linters (ruff, flake8), formatters, and codegen tools.

### `dis` — read the bytecode

`dis` disassembles a function into the bytecode CPython actually runs — invaluable for the
performance work in Phase 7:

```python
import dis
dis.dis(lambda x: x + 1)
#   LOAD_FAST   x
#   LOAD_CONST  1
#   BINARY_OP   + 
#   RETURN_VALUE
```

You don't write bytecode, but reading it demystifies why one construct is faster than
another (e.g., a local-variable lookup vs a global one).

## Milestone Project — a declarative ORM/schema

Combine descriptors + `__set_name__` + `__init_subclass__` into the pattern that powers
Pydantic and Django: **typed fields declared as class attributes, validation on every
assignment, automatic field collection, and model auto-registration.** The reference below
was **run**, with real output shown.

Requirements:

1. A `Field` descriptor base with typed subclasses (`Integer`, `String`) that validate on
   assignment and support constraints (min/max, maxlen).
2. `__set_name__` so fields know their own names and store per-instance values.
3. A `Model` base using `__init_subclass__` to (a) collect its `Field`s and (b) register the
   model in a class registry.
4. `Model.__init__(**kwargs)` that requires all fields, rejects unknowns, and validates each.

<details><summary>Reference solution (verified output)</summary>

```python
"""A tiny declarative schema/ORM-lite — the pattern behind Pydantic/Django models."""

class Field:
    """Base descriptor: validates on set, stores under a private per-instance name."""
    def __set_name__(self, owner, name):        # fires at class creation
        self.name = name
        self.storage = f"_{name}"

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return getattr(obj, self.storage)

    def __set__(self, obj, value):              # data descriptor -> validate every write
        setattr(obj, self.storage, self.validate(value))

    def validate(self, value):
        return value


class Integer(Field):
    def __init__(self, *, min=None, max=None):
        self.min, self.max = min, max

    def validate(self, value):
        if not isinstance(value, int) or isinstance(value, bool):
            raise TypeError(f"{self.name} must be int, got {type(value).__name__}")
        if self.min is not None and value < self.min:
            raise ValueError(f"{self.name} must be >= {self.min}")
        if self.max is not None and value > self.max:
            raise ValueError(f"{self.name} must be <= {self.max}")
        return value


class String(Field):
    def __init__(self, *, maxlen=None):
        self.maxlen = maxlen

    def validate(self, value):
        if not isinstance(value, str):
            raise TypeError(f"{self.name} must be str, got {type(value).__name__}")
        if self.maxlen is not None and len(value) > self.maxlen:
            raise ValueError(f"{self.name} exceeds maxlen {self.maxlen}")
        return value


class Model:
    registry: dict[str, type] = {}

    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        cls._fields = {n: v for n, v in vars(cls).items() if isinstance(v, Field)}
        Model.registry[cls.__name__] = cls

    def __init__(self, **kwargs):
        missing = set(self._fields) - set(kwargs)
        if missing:
            raise TypeError(f"missing fields: {sorted(missing)}")
        unknown = set(kwargs) - set(self._fields)
        if unknown:
            raise TypeError(f"unknown fields: {sorted(unknown)}")
        for name, value in kwargs.items():
            setattr(self, name, value)          # -> Field.__set__ -> validate

    def __repr__(self):
        inner = ", ".join(f"{n}={getattr(self, n)!r}" for n in self._fields)
        return f"{type(self).__name__}({inner})"


class Trade(Model):                              # declarative!
    symbol = String(maxlen=10)
    qty = Integer(min=1)
    price = Integer(min=0)


t = Trade(symbol="INFY", qty=10, price=1500)
print(t)                     # Trade(symbol='INFY', qty=10, price=1500)
print(Model.registry)        # {'Trade': <class 'Trade'>}
t.qty = 25                   # re-validates on assignment
```

**Verified output:**
```
created: Trade(symbol='INFY', qty=10, price=1500)
registry: ['Trade']
fields: ['symbol', 'qty', 'price']
after update: Trade(symbol='INFY', qty=25, price=1500)
rejected: qty must be >= 1
rejected: symbol exceeds maxlen 10
rejected: qty must be int, got str
rejected: missing fields: ['price']
```

**How the pieces cooperate:**

| Mechanism | Role |
|---|---|
| `Field.__set__` (data descriptor) | validates on *every* assignment, incl. re-assignment |
| `__set_name__` | each field learns its name → its private storage slot |
| `__init_subclass__` | collects `_fields` and registers the model, after `__set_name__` fires |
| `__get__`/`getattr` | reads the validated value back |

That's essentially a miniature Pydantic. Real libraries add type coercion, nested models,
serialization, and better errors — but the skeleton is exactly this.
