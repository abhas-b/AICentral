# Phase 4 — The Type System & Static Analysis

*Deep Python Mastery series · Tutorial 4 of the roadmap*

Type hints turn Python's "run it and find out" into "catch it before it runs." They don't
change runtime behavior at all — they're a parallel language a **static checker** (mypy or
pyright), your IDE, and human readers use to reason about your code. This phase takes you
from `x: int` to typing generic decorators with `ParamSpec` and designing interfaces with
`Protocol`. Every mypy result below was **actually run** — the errors, the revealed types,
the strict-mode passes are real output, not illustrations.

> **Prerequisites:** functions/decorators (tutorial 2), generators (tutorial 3), the data
> model (tutorial 1). **Tooling:** `pip install mypy` (or use pyright). **Python:** 3.10+;
> a few forms are flagged 3.11/3.12.

---

## What type hints are (and are not)

```python
def add(a: int, b: int) -> int:
    return a + b
```

- Hints are **not enforced at runtime.** `add("x", "y")` runs fine and returns `"xy"` —
  Python ignores the annotations when executing.
- Hints **are** read by static checkers, editors (autocomplete, refactoring), and some
  libraries (Pydantic, dataclasses, FastAPI) that inspect `__annotations__`.
- Python uses **gradual typing**: annotate as much or as little as you like. Unannotated
  code is treated as `Any` (unchecked). You can adopt types incrementally.

The value: a type checker reads your whole codebase and flags mismatches — wrong argument
types, `None` where a value is required, missing return paths, typos in attribute names —
before you ever run it. On a large trading/data codebase this catches a whole class of bugs
that otherwise surface only in production.

## 1. The basics

Annotate variables, parameters, and returns. Built-in containers are generic since 3.9:

```python
name: str = "Abhas"
prices: list[float] = [100.0, 101.5]
positions: dict[str, int] = {"INFY": 10}
pair: tuple[str, int] = ("INFY", 10)
maybe: int | None = None            # 3.10+ union syntax

def total(values: list[float]) -> float:
    return sum(values)

def find(symbol: str) -> int | None:  # may return an int or None
    return positions.get(symbol)
```

Key building blocks:

- **`X | None`** (equivalently `Optional[X]`) — "an X or nothing." The most common hint.
  Prefer the `|` form on 3.10+.
- **`A | B`** (equivalently `Union[A, B]`) — one of several types.
- **`Any`** — opts *out* of checking; assignable to and from anything. Use sparingly; it's
  an escape hatch, not a default.
- **`object`** — the top type. *Everything* is an `object`, but you can do almost nothing
  with an `object` until you narrow it (unlike `Any`). Reach for `object` when you truly
  accept anything but want the checker to keep protecting you.

The `Any` vs `object` distinction matters: `Any` disables the checker; `object` keeps it on
and forces you to narrow before use. Choose `object` when you can.

## 2. Running a type checker

Types are only worth as much as the tool that checks them. Install and run mypy:

```bash
pip install mypy
mypy yourfile.py            # check one file
mypy your_package/          # check a package
mypy --strict yourfile.py   # turn on all the strict flags (aim for this)
```

**`reveal_type(x)`** is a checker-only helper: mypy prints the type it inferred (remove it
before shipping, or import `from typing import reveal_type` on 3.11+ to keep the file
runnable):

```python
x = [1, 2, 3]
reveal_type(x)      # mypy note: Revealed type is "builtins.list[builtins.int]"
```

**Gradual adoption & `# type: ignore`.** Start loose, tighten over time. When a line
genuinely can't be typed (third-party gap, a checker limitation), silence *that line*
precisely: `# type: ignore[error-code]` — with the specific code, never a bare ignore, so
you don't accidentally mask new errors later.

**Strict mode** (`--strict`) enables the flags that make types actually load-bearing:
disallowing untyped functions, untyped calls, implicit `Any`, and more. Treat a clean
`mypy --strict` as the bar for library-quality code.

## 3. Precise & special types

Beyond the basics, the checker can express very specific shapes.

### `Literal` — exact values, not just the type

```python
from typing import Literal

Mode = Literal["backtest", "paper", "live"]

def run(mode: Mode) -> None: ...

run("live")        # ok
run("shadow")      # mypy error: not a valid Mode
```

`Literal` restricts to *specific values* — invaluable for string "enums", flags, and modes.
Real mypy output when you pass a bad value (from the milestone):

```
error: Argument 1 to "describe_mode" has incompatible type "Literal['shadow']";
       expected "Literal['backtest', 'paper', 'live']"  [arg-type]
```

### `Final` and `ClassVar`

```python
from typing import Final, ClassVar

MAX_RETRIES: Final = 3        # reassigning MAX_RETRIES later is an error

class Account:
    bank_name: ClassVar[str] = "HDFC"   # a class attribute, not per-instance
    def __init__(self, balance: float) -> None:
        self.balance = balance          # inferred instance attribute
```

`Final` forbids reassignment (constants); `ClassVar` marks a class-level attribute so the
checker won't confuse it with an instance field (and dataclasses won't treat it as one).

### `TypedDict` — dicts with a fixed shape

```python
from typing import TypedDict, Required, NotRequired   # Required/NotRequired: 3.11+

class RiskConfig(TypedDict):
    max_position: int
    stop_loss_pct: float

cfg: RiskConfig = {"max_position": 100_000, "stop_loss_pct": 2.0}   # keys/types checked
# missing a key or wrong type -> mypy error
```

`total=False` in the class signature makes *all* keys optional; `Required[...]`/
`NotRequired[...]` (3.11+) tune it per key. Great for typing JSON/config payloads without a
full class.

### `NewType`, `Annotated`, `cast`, `assert_type`

```python
from typing import NewType, Annotated, cast, assert_type

UserId = NewType("UserId", int)         # a DISTINCT type at check time; an int at runtime
def load(uid: UserId) -> None: ...
load(UserId(42))                        # ok
# load(42)                              # mypy error: int is not UserId

Age = Annotated[int, "years"]           # attach metadata to a type (used by Pydantic etc.)

raw: object = get_json()
value = cast(int, raw)                  # "trust me, it's an int" — no runtime check
assert_type(value, int)                 # assert the checker agrees (3.11+); no-op at runtime
```

- `NewType` gives you a semantically distinct type (a `UserId` isn't just any `int`) with
  zero runtime cost — catches "passed the wrong integer" bugs.
- `Annotated[T, meta]` carries extra info alongside `T`; libraries read the metadata.
- `cast` overrides the checker (use rarely — it's an assertion, not a conversion).
- `assert_type` documents and enforces an expected inferred type.

## 4. Generics — write once, keep the type

Generics let a function or class work over *any* type while preserving it — so the checker
knows `Stack[int].pop()` returns an `int`, not "something."

### `TypeVar` and generic functions

```python
from typing import TypeVar

T = TypeVar("T")

def first(items: list[T]) -> T:     # returns the SAME type it received
    return items[0]

reveal_type(first([1, 2, 3]))       # int
reveal_type(first(["a", "b"]))      # str
```

Without the `TypeVar`, you'd have to annotate the return as `Any` and lose all downstream
checking. `T` ties the input element type to the return type.

### Bounded and constrained TypeVars

```python
from typing import TypeVar

# BOUND: T must be a subtype of a given type (an upper bound)
NumT = TypeVar("NumT", bound=float)   # any float-like (int is a subtype of float here)

def clamp(x: NumT, lo: NumT, hi: NumT) -> NumT:
    return max(lo, min(x, hi))

# CONSTRAINED: T must be EXACTLY one of a fixed set
StrOrBytes = TypeVar("StrOrBytes", str, bytes)   # str or bytes, nothing else

def join(sep: StrOrBytes, parts: list[StrOrBytes]) -> StrOrBytes:
    return sep.join(parts)
```

- `bound=X` → "any subtype of X."
- `(A, B)` → "exactly A or exactly B" (not their common supertype).

### Generic classes with `Generic[T]`

```python
from typing import Generic, TypeVar

T = TypeVar("T")

class Stack(Generic[T]):
    def __init__(self) -> None:
        self._items: list[T] = []
    def push(self, item: T) -> None:
        self._items.append(item)
    def pop(self) -> T:
        return self._items.pop()

s: Stack[int] = Stack()
s.push(10)
reveal_type(s.pop())      # int
# s.push("oops")          # mypy error: expected int
```

### PEP 695 — the modern syntax (Python 3.12+)

3.12 added inline type-parameter syntax: no `TypeVar`/`Generic` imports, the parameter is
declared right on the `def`/`class`, and `type` introduces aliases. **Verified output:**

```python
def first[T](items: list[T]) -> T:      # generic function
    return items[0]

class Stack[T]:                         # generic class
    def __init__(self) -> None:
        self._items: list[T] = []
    def push(self, item: T) -> None: self._items.append(item)
    def pop(self) -> T: return self._items.pop()

type Vector = list[float]               # a type alias

reveal_type(first([1, 2, 3]))           # note: Revealed type is "int"
s: Stack[str] = Stack(); s.push("a")
reveal_type(s.pop())                    # note: Revealed type is "str"
# mypy: Success: no issues found
```

Use PEP 695 on 3.12+ (cleaner); use `TypeVar`/`Generic` when you must support older versions.

### Variance (the concept that trips everyone)

Is a `Stack[int]` usable where a `Stack[object]` is expected? Usually **no** — because you
could then `push` a `str` into it and corrupt the int stack. This is **variance**:

- **Invariant** (the default): `Container[int]` is *not* a `Container[object]`. Mutable
  containers are invariant.
- **Covariant**: if `int` is-a `object`, then `Producer[int]` is-a `Producer[object]`.
  Read-only producers can be covariant (`TypeVar("T_co", covariant=True)`).
- **Contravariant**: the reverse — write-only consumers (`TypeVar("T_ct",
  contravariant=True)`).

You rarely declare variance by hand, but understanding it explains *why* mypy sometimes
refuses an assignment that "looks" fine. Rule of thumb: mutable = invariant; if you only
produce values, covariance may be safe; if you only consume, contravariance.

**A real variance gotcha (from building the milestone).** I wrote a `Comparable` protocol
with `def __lt__(self, other: object)`, then called `maximum([1, 2, 3])`. mypy rejected it:

```
error: Value of type variable "CT" of "maximum" cannot be "int"  [type-var]
```

Why? `int.__lt__` only accepts `int` (a *narrower* parameter than `object`), so `int`
doesn't structurally satisfy a protocol demanding `__lt__(other: object)` — method
parameters are contravariant. The fix (what the standard library's own typeshed uses) is
`def __lt__(self, other: Any)`, because `Any` is bidirectionally compatible. After that,
`maximum([1, 2, 3])` checks clean. Keep this in your pocket — it's the #1 confusion with
comparison protocols.

## 5. Typing callables and decorators

This is the payoff for your Phase 2 decorator work: making decorators keep the signature of
what they wrap, under the checker's eye.

### `Callable`

```python
from collections.abc import Callable

# Callable[[arg types], return type]
handler: Callable[[int, str], bool]
noarg: Callable[[], None]
anyargs: Callable[..., int]        # ... = "any arguments"
```

### `ParamSpec` + `Concatenate` — signature-preserving decorators

A naive decorator typed `Callable[..., Any]` erases the wrapped function's signature — the
checker can no longer verify calls to the decorated function. **`ParamSpec`** captures the
*whole parameter list* so it survives:

```python
import functools, time
from collections.abc import Callable
from typing import ParamSpec, TypeVar

P = ParamSpec("P")      # captures the parameter signature
R = TypeVar("R")        # captures the return type

def timed(func: Callable[P, R]) -> Callable[P, R]:
    @functools.wraps(func)
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:   # note P.args / P.kwargs
        start = time.perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            print(f"{func.__name__}: {(time.perf_counter()-start)*1000:.2f} ms")
    return wrapper

@timed
def position_size(config: dict[str, int], price: float) -> int:
    return int(config["max_position"] / price)
```

Does the signature survive the decorator? **Verified with `reveal_type`:**

```
note: Revealed type is "def (config: ..., price: float) -> int"
```

mypy still sees the full `(config, price: float) -> int` signature *through* `@timed` — so
`position_size(cfg, "1500")` is caught as a type error. That's the difference between a
decorator that helps the checker and one that blinds it.

`Concatenate` handles decorators that *add or remove* leading parameters, e.g. injecting a
first argument: `Callable[Concatenate[Connection, P], R] -> Callable[P, R]`.

## 6. Protocols — structural typing (usually better than ABCs)

An **ABC** says "you're a Shape if you *inherit* from Shape" (nominal typing). A
**`Protocol`** says "you're `Sized` if you *have* a `__len__`" (structural typing) — no
inheritance required. This matches Python's duck-typing culture and lets you type things you
don't own.

```python
from typing import Protocol, runtime_checkable

class SupportsClose(Protocol):
    def close(self) -> None: ...

def shutdown(resource: SupportsClose) -> None:
    resource.close()

# ANY object with a close() method satisfies SupportsClose — no subclassing:
class Connection:
    def close(self) -> None:
        print("closed")

shutdown(Connection())      # ok — structural match
```

- No `class Connection(SupportsClose)` needed; having `close()` is enough.
- Add `@runtime_checkable` to allow `isinstance(x, SupportsClose)` at runtime (it only
  checks method *names* exist, not signatures — a limitation to know).
- Protocols can require attributes, methods, even other dunders.

**Protocol vs ABC:** use a `Protocol` for interfaces, especially across code you don't
control or when you want loose coupling; use an ABC when you want shared implementation
(mixin methods) or to *force* explicit subclassing. Protocols are the more Pythonic default
for pure interfaces.

### Exercise 6

Define a `Named` protocol requiring a `name: str` attribute. Write `greet(x: Named) -> str`
returning `f"Hello {x.name}"`. Show it accepts any object with a `name` attribute without
inheritance.

<details><summary>Solution</summary>

```python
from typing import Protocol

class Named(Protocol):
    name: str

def greet(x: Named) -> str:
    return f"Hello {x.name}"

class User:               # does NOT inherit Named
    def __init__(self, name: str) -> None:
        self.name = name

print(greet(User("Abhas")))    # Hello Abhas  — structural match
# greet(object())              # mypy error: object has no attribute "name"
```
</details>

## 7. Type narrowing & exhaustiveness

The checker tracks how you *narrow* a broad type down to a specific one.

```python
def describe(x: int | str | None) -> str:
    if x is None:
        return "nothing"          # here x is None
    if isinstance(x, int):
        return f"int {x + 1}"     # here x is int — arithmetic is safe
    return x.upper()              # here x must be str — string methods are safe
```

`isinstance`, `is None`, `assert`, and comparisons all narrow the type in the branches that
follow. The checker *knows* `x` is a `str` on the last line, so `.upper()` is allowed.

### `TypeGuard` / `TypeIs` — custom narrowing functions

```python
from typing import TypeGuard

def all_strings(items: list[object]) -> TypeGuard[list[str]]:
    return all(isinstance(x, str) for x in items)

def process(items: list[object]) -> None:
    if all_strings(items):
        # inside here, the checker treats items as list[str]
        print(" ".join(items))
```

A `TypeGuard[T]` return type tells the checker "if this returns True, the argument is a `T`."
`TypeIs` (3.13) is a refined version that also narrows in the `else` branch.

### `Never` and exhaustiveness with `match`

`Never` (a.k.a. `NoReturn`) is the *bottom* type — no value has it. `assert_never(x)` lets
you demand that a `match`/`if` chain is exhaustive; if you later add a case and forget to
handle it, the checker flags the `assert_never` line:

```python
from typing import Literal, assert_never

Mode = Literal["backtest", "paper", "live"]

def label(mode: Mode) -> str:
    match mode:
        case "backtest": return "sim"
        case "paper":    return "paper"
        case "live":     return "live"
        case _ as unreachable:
            assert_never(unreachable)   # mypy errors here if a Mode value is unhandled
```

This is a powerful pattern: add a fourth `Mode` and mypy immediately points at the
`assert_never`, forcing you to handle it. Exhaustiveness checking turns your type
definitions into a to-do list the compiler maintains.

## 8. Special forms & practical tooling

### `Self`, `@override`, `@overload`

```python
from typing import Self, overload

class Builder:
    def __init__(self) -> None:
        self.parts: list[str] = []
    def add(self, part: str) -> Self:      # returns the same (sub)class — chaining
        self.parts.append(part)
        return self

Builder().add("a").add("b")   # Self makes the fluent chain type correctly, even in subclasses


class Base:
    def run(self) -> None: ...

class Child(Base):
    def run(self) -> None:     # @override (3.12) errors if this doesn't actually override
        ...


@overload
def parse(x: int) -> str: ...
@overload
def parse(x: str) -> int: ...
def parse(x: int | str) -> int | str:      # the single real implementation
    return str(x) if isinstance(x, int) else int(x)

reveal_type(parse(5))     # str
reveal_type(parse("5"))   # int
```

- `Self` (3.11) types methods returning their own instance — correct for fluent builders and
  alternate constructors, even under subclassing.
- `@override` (3.12) makes "I meant to override a base method" checkable (catches renames).
- `@overload` gives one function multiple typed signatures — the checker picks the matching
  one per call, so `parse(int)` is known to return `str`.

### Stub files and import cycles

- **`.pyi` stub files** hold type information separately from implementation — used to type
  C extensions or third-party libraries that ship no hints.
- **`typing.TYPE_CHECKING`** is a constant that's `False` at runtime but `True` for the
  checker. Import types used *only in annotations* under it to break circular imports:

```python
from __future__ import annotations   # makes all annotations strings (lazy)
from typing import TYPE_CHECKING

if TYPE_CHECKING:
    from .orders import Order        # not imported at runtime -> no import cycle

def process(order: Order) -> None:   # fine: annotation is a string, resolved by the checker
    ...
```

## Milestone Project — fully type a module to `--strict`

Take a small module, add complete hints, and get a clean `mypy --strict` run. It must
include: a **`ParamSpec`-typed decorator**, a **`Protocol`**, a **bounded-generic function**,
a **`TypedDict`**, a **`Literal`**, and **exhaustiveness** via `assert_never`.

Below is a reference module that was **run under `mypy --strict` (clean) and executed** —
with the real outputs shown.

<details><summary>Reference solution (verified)</summary>

```python
"""risk.py — a small, fully-typed module. Passes `mypy --strict`."""
from __future__ import annotations

import functools
import time
from collections.abc import Callable, Iterable
from typing import Any, Literal, ParamSpec, Protocol, TypedDict, TypeVar, assert_never

P = ParamSpec("P")
R = TypeVar("R")


def timed(func: Callable[P, R]) -> Callable[P, R]:
    """Signature-preserving timing decorator (ParamSpec keeps the wrapped signature)."""
    @functools.wraps(func)
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        start = time.perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            print(f"{func.__name__} took {(time.perf_counter()-start)*1000:.2f} ms")
    return wrapper


class Comparable(Protocol):
    # NOTE: other must be `Any`, not `object` — else int/float won't satisfy the protocol
    def __lt__(self, other: Any, /) -> bool: ...


CT = TypeVar("CT", bound=Comparable)


def maximum(items: Iterable[CT]) -> CT:
    """Generic maximum over any comparable type."""
    iterator = iter(items)
    try:
        best = next(iterator)
    except StopIteration:
        raise ValueError("maximum() arg is empty") from None
    for candidate in iterator:
        if best < candidate:
            best = candidate
    return best


class RiskConfig(TypedDict):
    max_position: int
    stop_loss_pct: float


Mode = Literal["backtest", "paper", "live"]


def describe_mode(mode: Mode) -> str:
    if mode == "backtest":
        return "Historical simulation"
    elif mode == "paper":
        return "Simulated live trading"
    elif mode == "live":
        return "Real orders on the exchange"
    else:
        assert_never(mode)      # exhaustiveness guard


@timed
def position_size(config: RiskConfig, price: float) -> int:
    return int(config["max_position"] / price)


if __name__ == "__main__":
    cfg: RiskConfig = {"max_position": 100_000, "stop_loss_pct": 2.0}
    print(position_size(cfg, 1500.0))       # 66
    print(maximum([3, 1, 4, 1, 5, 9, 2, 6]))  # 9
    print(describe_mode("live"))            # Real orders on the exchange
```

**`mypy --strict risk.py`:**
```
Success: no issues found in 1 source file
```

**Does `@timed` preserve the signature? (`reveal_type(position_size)`):**
```
note: Revealed type is "def (config: TypedDict('RiskConfig', {...}), price: float) -> int"
```
The full signature survives the decorator — so wrong calls are still caught.

**Errors mypy catches on misuse:**
```
error: Argument 2 to "position_size" has incompatible type "str"; expected "float"
error: Argument 1 to "describe_mode" has incompatible type "Literal['shadow']";
       expected "Literal['backtest', 'paper', 'live']"
error: Value of type variable "CT" of "maximum" cannot be "object"
```

Every one of those is a real bug the checker stops before runtime.

- Introduce a fourth `Mode` and watch mypy point at `assert_never` until you handle it.
- Split the config types into a `.pyi` stub and check the module still passes.
